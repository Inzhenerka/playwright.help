`Credentials` — это виртуальный аутентификатор WebAuthn, область действия которого ограничена [BrowserContext]. Он позволяет тестам регистрировать ключи доступа (passkey) и обрабатывать процедуры `navigator.credentials.create()` / `navigator.credentials.get()` на странице без реального аутентификатора или аппаратного ключа безопасности.

Существует три распространённых способа его использования:

**Использование: предварительное добавление известных учётных данных**

```java
BrowserContext context = browser.newContext();

// Ключ доступа, который ваш бэкенд уже подготовил для тестового пользователя.
context.credentials().create("example.com", new Credentials.CreateOptions()
    .setId(knownCredentialId) // base64url
    .setUserHandle(knownUserHandle) // base64url
    .setPrivateKey(knownPrivateKey) // base64url PKCS#8 (DER)
    .setPublicKey(knownPublicKey)); // base64url SPKI (DER)
context.credentials().install();

Page page = context.newPage();
page.navigate("https://example.com/login");
// На вызов navigator.credentials.get() со страницы возвращается предварительно добавленный ключ доступа.
```

**Использование: получение учётных данных и их повторное использование**

```java
// Подготовительный тест: разрешаем приложению зарегистрировать ключ доступа, а затем сохраняем его.
BrowserContext context = browser.newContext();
context.credentials().install();

Page page = context.newPage();
page.navigate("https://example.com/register");
page.getByRole(AriaRole.BUTTON, new Page.GetByRoleOptions().setName("Create a passkey")).click();

// Получаем ключ доступа, зарегистрированный страницей, — он включает закрытый ключ.
VirtualCredential credential = context.credentials().get(
    new Credentials.GetOptions().setRpId("example.com")).get(0);
Files.writeString(Paths.get("playwright/.auth/passkey.json"), new Gson().toJson(credential));
```

```java
// Последующий тест: предварительно добавляем сохранённый ключ доступа, чтобы он уже был зарегистрирован в приложении.
VirtualCredential credential = new Gson().fromJson(
    Files.readString(Paths.get("playwright/.auth/passkey.json")), VirtualCredential.class);
BrowserContext context = browser.newContext();
context.credentials().create(credential.rpId, new Credentials.CreateOptions()
    .setId(credential.id)
    .setUserHandle(credential.userHandle)
    .setPrivateKey(credential.privateKey)
    .setPublicKey(credential.publicKey)
    .setSignCount(credential.signCount));
context.credentials().install();

Page page = context.newPage();
page.navigate("https://example.com/login");
// navigator.credentials.get() возвращает сохранённый ключ доступа — вход выполнен.
```

**Использование: сохранение учётных данных в состоянии хранилища и последующее восстановление**

Примеры сохранения и восстановления состояния хранилища приведены в [руководстве по аутентификации](../auth.mdx).

## Методы

### create {/* #credentials-create */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.create</x-search>

Предварительно добавляет виртуальные учётные данные WebAuthn и возвращает их.

Если указан только [rpId](/api/class-credentials.mdx#credentials-create-option-rp-id), генерирует новую пару ключей **ECDSA P-256**, идентификатор учётных данных и идентификатор пользователя (user handle). Добавленные учётные данные являются обнаруживаемыми (резидентными), поэтому страница может получать их как в сценариях с вводом имени пользователя перед использованием ключа доступа, так и в сценариях использования ключа доступа без ввода имени пользователя. Возвращаемый объект содержит закрытый и открытый ключи, поэтому его можно сохранить на диск и предварительно добавить в последующем тесте.

Чтобы **импортировать известные учётные данные**, укажите все четыре параметра одновременно: [setId](/api/class-credentials.mdx#credentials-create-option-id), [setUserHandle](/api/class-credentials.mdx#credentials-create-option-user-handle), [setPrivateKey](/api/class-credentials.mdx#credentials-create-option-private-key) и [setPublicKey](/api/class-credentials.mdx#credentials-create-option-public-key). Также передайте [setSignCount](/api/class-credentials.mdx#credentials-create-option-sign-count), чтобы продолжить отсчёт со значения счётчика подписей, которое доверяющая сторона уже получила.

Вызовите [Credentials.install()](/api/class-credentials.mdx#credentials-install) перед переходом на страницу, использующую WebAuthn.

**Использование**

```java
Credentials.create(rpId);
Credentials.create(rpId, options);
```

**Аргументы**
- `rpId` [String]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-rp-id"/><a href="#credentials-create-option-rp-id" class="list-anchor">#</a>
  
  Идентификатор доверяющей стороны (обычно фактический домен сайта).
- `options` `Credentials.CreateOptions` *(необязательно)*
  - `setId` [String] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-id"/><a href="#credentials-create-option-id" class="list-anchor">#</a>
    
    Идентификатор учётных данных в кодировке base64url. Если не указан, генерируется автоматически.
  - `setPrivateKey` [String] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-private-key"/><a href="#credentials-create-option-private-key" class="list-anchor">#</a>
    
    Закрытый ключ в формате PKCS#8 (DER), закодированный в base64url. Если не указан, генерируется автоматически.
  - `setPublicKey` [String] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-public-key"/><a href="#credentials-create-option-public-key" class="list-anchor">#</a>
    
    Открытый ключ в формате SPKI (DER), закодированный в base64url. Если не указан, генерируется автоматически.
  - `setSignCount` [int] *(необязательно)* <font size="2">Добавлено в: v1.64</font><a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-sign-count"/><a href="#credentials-create-option-sign-count" class="list-anchor">#</a>
    
    Начальное значение [счётчика подписей](https://www.w3.org/TR/webauthn-2/#signature-counter). Счётчик увеличивается на единицу при каждом успешном подтверждении аутентификации через `navigator.credentials.get()`, поэтому первое подтверждение сообщает значение `signCount + 1`. По умолчанию — `0`.
  - `setUserHandle` [String] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-user-handle"/><a href="#credentials-create-option-user-handle" class="list-anchor">#</a>
    
    Идентификатор пользователя (user handle) в кодировке base64url. Если не указан, генерируется автоматически.

**Возвращает**
- Create<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-return"/><a href="#credentials-create-return" class="list-anchor">#</a>
  - `id` [String]
    
    Идентификатор учётных данных в кодировке base64url.
  - `rpId` [String]
    
    Идентификатор доверяющей стороны.
  - `userHandle` [String]
    
    Идентификатор пользователя (user handle) в кодировке base64url.
  - `privateKey` [String]
    
    Закрытый ключ в формате PKCS#8 (DER), закодированный в base64url.
  - `publicKey` [String]
    
    Открытый ключ в формате SPKI (DER), закодированный в base64url.
  - `signCount` [int]
    
    Счётчик подписей: значение, переданное доверяющей стороне в последнем подтверждении аутентификации.

### delete {/* #credentials-delete */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.delete</x-search>

Удаляет учётные данные из аутентификатора по их идентификатору. Работает с любыми учётными данными, которые в данный момент хранятся в аутентификаторе, — как с предварительно добавленными через [Credentials.create()](/api/class-credentials.mdx#credentials-create), так и с теми, которые страница зарегистрировала самостоятельно вызовом `navigator.credentials.create()`.

**Использование**

```java
Credentials.delete(id);
```

**Аргументы**
- `id` [String]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-delete-option-id"/><a href="#credentials-delete-option-id" class="list-anchor">#</a>
  
  Идентификатор учётных данных в кодировке base64url.

**Возвращает**
- [void]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-delete-return"/><a href="#credentials-delete-return" class="list-anchor">#</a>

### get {/* #credentials-get */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.get</x-search>

Возвращает все учётные данные, которые в данный момент хранятся в аутентификаторе, с возможностью фильтрации по [setRpId](/api/class-credentials.mdx#credentials-get-option-rp-id) или [setId](/api/class-credentials.mdx#credentials-get-option-id). Сюда входят как учётные данные, предварительно добавленные через [Credentials.create()](/api/class-credentials.mdx#credentials-create), так и учётные данные, которые страница зарегистрировала самостоятельно вызовом `navigator.credentials.create()`.

Каждый возвращаемый объект учётных данных содержит закрытый и открытый ключи, а также текущее значение счётчика подписей. Поэтому ключ доступа, только что зарегистрированный приложением, можно сохранить и предварительно добавить в последующем тесте с помощью [Credentials.create()](/api/class-credentials.mdx#credentials-create) — см. второй пример в обзоре класса.

**Использование**

```java
Credentials.get();
Credentials.get(options);
```

**Аргументы**
- `options` `Credentials.GetOptions` *(необязательно)*
  - `setId` [String] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-get-option-id"/><a href="#credentials-get-option-id" class="list-anchor">#</a>
    
    Возвращать только учётные данные с этим идентификатором в кодировке base64url.
  - `setRpId` [String] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-get-option-rp-id"/><a href="#credentials-get-option-rp-id" class="list-anchor">#</a>
    
    Возвращать только учётные данные для указанного идентификатора доверяющей стороны.

**Возвращает**
- [List]&lt;Get&gt;<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-get-return"/><a href="#credentials-get-return" class="list-anchor">#</a>
  - `id` [String]
    
    
  - `rpId` [String]
    
    
  - `userHandle` [String]
    
    
  - `privateKey` [String]
    
    
  - `publicKey` [String]
    
    
  - `signCount` [int]

### install {/* #credentials-install */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.install</x-search>

Устанавливает виртуальный аутентификатор WebAuthn в контекст, переопределяя `navigator.credentials.create()` и `navigator.credentials.get()` на всех текущих и будущих страницах. Вызовите этот метод до первого обращения страницы к `navigator.credentials`.

Обязательный вызов: пока не вызван [Credentials.install()](/api/class-credentials.mdx#credentials-install), перехват не выполняется и страница использует встроенную реализацию WebAuthn платформы (либо WebAuthn остаётся недоступным, если такой реализации нет). Предварительное добавление учётных данных через [Credentials.create()](/api/class-credentials.mdx#credentials-create) без установки аутентификатора заполняет его, но страница никогда не получит доступ к этим учётным данным.

**Использование**

```java
Credentials.install();
```

**Возвращает**
- [void]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-install-return"/><a href="#credentials-install-return" class="list-anchor">#</a>
