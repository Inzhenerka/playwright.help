# Сессии и панель управления

По умолчанию CLI хранит профиль браузера в памяти — файлы cookie и состояние хранилищ сохраняются между вызовами CLI в рамках одной сессии, но теряются при закрытии браузера.

## Именованные сессии

Запустите несколько изолированных экземпляров браузера:

```bash
playwright-cli open https://playwright.dev
playwright-cli -s=example open https://example.com --persistent
playwright-cli list
```

```txt
### Browsers
- default:
  - status: open
  - browser-type: chrome
  - user-data-dir: <in-memory>
  - headed: false
- example:
  - status: open
  - browser-type: chrome
  - user-data-dir: /Users/me/Library/Caches/ms-playwright/daemon/8f2c.../ud-example-chrome
  - headed: false
```

У каждой сессии есть собственный экземпляр браузера, файлы cookie, localStorage, IndexedDB, кеш, история навигации, открытые вкладки и журнал консоли.

`playwright-cli list --all` расширяет список, включая сессии из всех рабочих пространств, а также добавляет серверы браузеров Playwright
и локальные профили Chrome/Edge, к которым можно [подключиться](./commands/attach.mdx).

## Переменная окружения

```bash
PLAYWRIGHT_CLI_SESSION=todo-app claude .
```

Все команды `playwright-cli` в этой сессии агента используют экземпляр браузера `todo-app`.

## Сохранение профиля

### В памяти (по умолчанию)

Файлы cookie и данные хранилищ сохраняются между командами в рамках одной сессии, но теряются при закрытии браузера:

```bash
playwright-cli open https://example.com
```

### Сохранение на диск

Профиль сохраняется на диск и не теряется при перезапуске браузера. Это эквивалентно используемому по умолчанию режиму постоянного профиля в [Playwright MCP](/mcp/configuration/user-profile).

```bash
playwright-cli open https://example.com --persistent
```

Каталог профиля определяется рабочим пространством и именем сессии — `ud-<session>-<browser>`
внутри отдельного каталога рабочего пространства:

| Платформа | Расположение по умолчанию |
|----------|-----------------|
| macOS | `~/Library/Caches/ms-playwright/daemon/<workspace-hash>/` |
| Linux | `$XDG_CACHE_HOME/ms-playwright/daemon/<workspace-hash>/` (по умолчанию используется `~/.cache`) |
| Windows | `%LOCALAPPDATA%\ms-playwright\daemon\<workspace-hash>\` |

### Пользовательский каталог

```bash
playwright-cli open https://example.com --profile=./my-profile
```

## Управление сессиями

```bash
playwright-cli list                     # вывести список сессий в этом рабочем пространстве
playwright-cli list --all               # вывести список сессий во всех рабочих пространствах
playwright-cli -s=name close            # закрыть указанную сессию
playwright-cli -s=name detach           # отключиться, не закрывая подключённый браузер
playwright-cli close-all                # закрыть все браузеры
playwright-cli kill-all                 # принудительно завершить процессы (для браузеров, которые не отвечают)
playwright-cli -s=name delete-data      # удалить сохранённые данные профиля
```

`close` останавливает браузер, запущенный CLI. Для сессий, созданных с помощью `attach`, используйте `detach` — эта команда
завершает сессию, оставляя внешний браузер работающим. См. раздел [Подключение](./commands/attach.mdx).

## Панель управления

Откройте визуальную панель управления для наблюдения за всеми запущенными сессиями и управления ими:

```bash
playwright-cli show
```

Панель управления предоставляет следующие представления:

| Представление | Описание |
|------|-------------|
| **Сетка сессий** | Все активные сессии с трансляцией экрана в реальном времени, именем, URL и заголовком страницы. Нажмите, чтобы увеличить. |
| **Подробное представление сессии** | Область просмотра браузера в реальном времени с панелью вкладок, элементами навигации и полноценным удалённым управлением с помощью мыши и клавиатуры. Нажмите Escape, чтобы прекратить перехват ввода. |

Сценарии использования:
- Наблюдайте, как агенты программирования автоматизируют работу браузеров в фоновом режиме
- Берите управление на себя, когда агент не может пройти CAPTCHA или двухфакторную аутентификацию (2FA)
- Закрывайте неиспользуемые сессии или удаляйте данные через пользовательский интерфейс

### Параметры

```bash
playwright-cli show                     # запустить панель управления в фоновом режиме
playwright-cli -s=name show             # запустить панель и показать указанную сессию
playwright-cli show --port=0            # запустить как HTTP-сервер на случайном порту, блокируя выполнение команды
playwright-cli show --port=8080 --host=0.0.0.0
playwright-cli show --kill              # остановить фоновую службу панели управления
```

### Режим аннотирования

`show --annotate` превращает панель управления в инструмент обратной связи: пользователь выделяет прямоугольные области на текущей странице
и вводит комментарии, а команда возвращает скриншот с аннотациями, снимок отмеченной
области и заметки. Команда блокирует выполнение до тех пор, пока пользователь не закончит, что позволяет запрашивать проверку пользовательского
интерфейса или обратную связь по дизайну прямо в процессе автоматизации.

```bash
playwright-cli open https://example.com
playwright-cli show --annotate
```

## Сохранение и восстановление состояния

Сохраните состояние аутентификации для повторного использования в разных сессиях:

```bash
# Войдите в систему, затем сохраните состояние
playwright-cli state-save auth-state.json

# Позже: восстановите состояние в новой сессии
playwright-cli state-load auth-state.json
```

## Рабочий процесс: изолированное тестирование

```bash
# Сессия администратора
playwright-cli -s=admin open https://app.example.com --persistent
playwright-cli -s=admin state-load admin-auth.json
playwright-cli -s=admin goto /admin/settings

# Сессия пользователя
playwright-cli -s=user open https://app.example.com --persistent
playwright-cli -s=user state-load user-auth.json
playwright-cli -s=user goto /dashboard

# Наблюдение за обеими сессиями
playwright-cli show
```
