## Введение

Сервер Playwright MCP предоставляет возможности автоматизации браузера через [Model Context Protocol](https://modelcontextprotocol.io), позволяя большим языковым моделям (LLM) взаимодействовать с веб-страницами с помощью структурированных снимков дерева доступности. Он работает с VS Code, Cursor, Windsurf, Claude Desktop и любым другим MCP-клиентом — модели с поддержкой обработки изображений не требуются.

## Предварительные требования

Прежде чем начать, убедитесь, что у вас установлены:
- [Node.js](https://nodejs.org/) версии 20 или новее
- MCP-клиент: VS Code, Cursor, Windsurf, Claude Code, Claude Desktop или аналогичный

## Начало работы

### Установка

Добавьте сервер Playwright MCP в свой клиент, используя стандартную конфигурацию:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": [
        "@playwright/mcp@latest"
      ]
    }
  }
}
```

#### VS Code

Нажмите одну из кнопок ниже для прямой установки:

[<img src="https://img.shields.io/badge/VS_Code-VS_Code?style=flat-square&label=Install%20Server&color=0098FF" alt="Установить в VS Code" />](https://insiders.vscode.dev/redirect?url=vscode%3Amcp%2Finstall%3F%257B%2522name%2522%253A%2522playwright%2522%252C%2522command%2522%253A%2522npx%2522%252C%2522args%2522%253A%255B%2522%2540playwright%252Fmcp%2540latest%2522%255D%257D) [<img alt="Установить в VS Code Insiders" src="https://img.shields.io/badge/VS_Code_Insiders-VS_Code_Insiders?style=flat-square&label=Install%20Server&color=24bfa5" />](https://insiders.vscode.dev/redirect?url=vscode-insiders%3Amcp%2Finstall%3F%257B%2522name%2522%253A%2522playwright%2522%252C%2522command%2522%253A%2522npx%2522%252C%2522args%2522%253A%255B%2522%2540playwright%252Fmcp%2540latest%2522%255D%257D)

Или установите через CLI VS Code:

```bash
code --add-mcp '{"name":"playwright","command":"npx","args":["@playwright/mcp@latest"]}'
```

#### Cursor

[<img src="https://cursor.com/deeplink/mcp-install-dark.svg" alt="Установить в Cursor" />](https://cursor.com/en/install-mcp?name=Playwright&config=eyJjb21tYW5kIjoibnB4IEBwbGF5d3JpZ2h0L21jcEBsYXRlc3QifQ%3D%3D)

#### Claude Code

```bash
claude mcp add playwright npx @playwright/mcp@latest
```

#### Claude Desktop

Следуйте [руководству](https://modelcontextprotocol.io/quickstart/user) по установке MCP и используйте стандартную конфигурацию, приведённую выше.

#### Другие клиенты

Стандартная конфигурация работает с большинством MCP-клиентов, включая Windsurf, Cline, Goose, Kiro, Codex, Copilot CLI и другие. О том, где разместить конфигурацию, читайте в документации по MCP вашего клиента.

### Первое взаимодействие

После подключения сервера попросите своего ИИ-ассистента выполнить действия на веб-странице:

```txt
Перейди на https://demo.playwright.dev/todomvc и добавь несколько задач в список.
```

Ассистент воспользуется инструментами Playwright MCP, чтобы открыть браузер, перейти на страницу и взаимодействовать с элементами — всё это с помощью структурированных снимков дерева доступности, а не скриншотов.

## Основные возможности

### Снимки дерева доступности

Playwright MCP работает с деревом доступности страницы, а не с пикселями. При выполнении инструмент возвращает структурированный снимок, в котором показаны элементы страницы, их роли и текстовое содержимое. LLM использует ссылки на элементы из этих снимков для взаимодействия со страницей:

```txt
- heading "todos" [level=1]
- textbox "What needs to be done?" [ref=e5]
- listitem:
  - checkbox "Toggle Todo" [ref=e10]
  - text: "Buy groceries"
```

LLM читает этот снимок и использует `ref=e5` для ввода текста в текстовое поле или `ref=e10` для установки флажка.

### Взаимодействие со страницами

Playwright MCP предоставляет инструменты для всех распространённых действий в браузере:
-   **Навигация**: открытие URL-адресов, переход назад и вперёд, перезагрузка страниц.
-   **Нажатия и ввод текста**: нажатие на элементы, ввод текста, заполнение форм, выбор значений в раскрывающихся списках.
-   **Скриншоты**: создание снимков текущей страницы или отдельных элементов для визуальной проверки.
-   **Клавиатура и мышь**: нажатие клавиш, наведение указателя, перетаскивание элементов.
-   **Диалоговые окна**: подтверждение или отклонение диалоговых окон браузера.
-   **Вкладки**: создание, закрытие вкладок браузера и переключение между ними.

### Выполнение кода Playwright

Для сложных взаимодействий, выходящих за рамки отдельных вызовов инструментов, используйте инструмент `browser_run_code_unsafe`, чтобы выполнять скрипты Playwright напрямую. Этот инструмент выполняет произвольный JavaScript в процессе сервера Playwright и по своим возможностям эквивалентен удалённому выполнению кода (RCE) — включайте его только для доверенных MCP-клиентов:

```txt
Выполни этот код Playwright, чтобы проверить количество задач:
async (page) => {
  const count = await page.getByTestId('todo-count').textContent();
  return count;
}
```

### Мониторинг сети и имитация ответов

Анализируйте сетевой трафик и имитируйте ответы API:
-   **Просмотр сетевых запросов**: получение списка всех запросов, выполненных с момента загрузки страницы.
-   **Имитация маршрутов**: настройка сопоставления URL-адресов с шаблонами для возврата заданных ответов.
-   **Сообщения консоли**: доступ к выводу консоли браузера для отладки.

### Состояние хранилища

Сохраняйте и восстанавливайте состояние браузера, включая файлы cookie и localStorage:
-   **Сохранение состояния**: сохранение данных аутентификации и сеанса в файл.
-   **Восстановление состояния**: загрузка ранее сохранённого состояния в новый сеанс.
-   **Управление файлами cookie**: просмотр списка, получение, установка и удаление отдельных файлов cookie.

### Инструменты WebMCP

Страницы могут регистрировать собственные инструменты для агентов через экспериментальный API [WebMCP](https://webmachinelearning.github.io/webmcp/). Инструменты текущей вкладки предоставляются как MCP-инструменты с именами `webmcp_<tool>`.

Имена инструментов, их описания, схемы и результаты предоставляются страницей, поэтому рассматривайте их как недоверенные входные данные.

## Настройка

### Режим с графическим интерфейсом

По умолчанию Playwright MCP запускает браузер в режиме с графическим интерфейсом, чтобы вы могли видеть происходящее. Для запуска без графического интерфейса:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": [
        "@playwright/mcp@latest",
        "--headless"
      ]
    }
  }
}
```

### Выбор браузера

Выберите, какой браузер использовать:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": [
        "@playwright/mcp@latest",
        "--browser=firefox"
      ]
    }
  }
}
```

Поддерживаемые значения: `chrome`, `firefox`, `webkit`, `msedge`.

### Профиль пользователя

Playwright MCP поддерживает три режима работы с профилем:
-   **Постоянный (по умолчанию)**: состояние входа в систему и файлы cookie сохраняются между сеансами. Профиль хранится в `ms-playwright/mcp-{channel}-{workspace-hash}` в каталоге кеша вашей платформы, поэтому разные проекты автоматически получают отдельные профили. Путь можно переопределить с помощью `--user-data-dir`.
-   **Изолированный**: каждый сеанс начинается с чистого состояния. Для включения передайте `--isolated`. Начальное состояние можно загрузить с помощью `--storage-state`.
-   **Расширение браузера**: подключение к существующим вкладкам браузера с помощью [расширения Playwright](https://github.com/microsoft/playwright/blob/main/packages/extension/README.md). Для включения передайте `--extension`.

### Тайм-аут бездействия

Страница с непрерывной анимацией или отрисовкой потребляет ресурсы процессора всё время, пока открыт браузер, а сеанс агента может длиться часами. Поэтому браузер без графического интерфейса, запущенный сервером, закрывается через час без вызовов инструментов. Браузеры с графическим интерфейсом, а также браузеры, подключённые через `--cdp-endpoint` или `--extension`, автоматически не закрываются. Передайте `--idle-timeout`, чтобы задать тайм-аут в миллисекундах для любого режима, или `0`, чтобы отключить его:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": [
        "@playwright/mcp@latest",
        "--idle-timeout=300000"
      ]
    }
  }
}
```

Если за этот промежуток времени не завершился ни один вызов инструмента, браузер закрывается независимо от наличия графического интерфейса — так же, как если бы вы закрыли его вручную. Следующий вызов инструмента запускает новый браузер, поэтому агент снова выполняет переход на страницу. Таймер никогда не срабатывает во время выполнения вызова инструмента.
-   При использовании `--isolated` файлы cookie и данные хранилищ, находящиеся в памяти, теряются при закрытии из-за бездействия. Чтобы сохранить их, используйте постоянный профиль или `--storage-state`. У каждого клиента свой таймер: контекст бездействующего клиента закрывается, пока другие клиенты продолжают работать, а браузер закрывается, когда ни у одного клиента не остаётся контекста.
-   При использовании `--cdp-endpoint` или `--extension` браузер не принадлежит серверу, поэтому тайм-аут по умолчанию отсутствует, а явно заданный тайм-аут лишь отключает сервер от браузера, оставляя его страницы открытыми. При использовании `--extension` следующий вызов инструмента снова проходит процедуру подключения.
-   При использовании `--shared-browser-context` таймер охватывает всех клиентов: клиент, который бездействует, пока остальные продолжают работать, сохраняет свои вкладки и состояние, а общий браузер закрывается только после того, как каждый клиент бездействовал в течение заданного тайм-аута.

### Файл конфигурации

Для расширенной настройки используйте файл конфигурации в формате JSON:

```bash
npx @playwright/mcp@latest --config path/to/config.json
```

Файл конфигурации поддерживает параметры браузера, параметры контекста, сетевые правила, тайм-ауты и многое другое. Полную схему см. в [репозитории Playwright MCP](https://github.com/microsoft/playwright-mcp/blob/main/config.d.ts).

### Автономный сервер

При запуске браузера с графическим интерфейсом в системе без дисплея или из рабочих процессов IDE запустите MCP-сервер отдельно, используя HTTP-транспорт:

```bash
npx @playwright/mcp@latest --port 8931
```

В HTTP-сеансах используется тайм-аут проверки активности в пять секунд. Если ваш MCP-клиент или прокси не отвечает на ping-запросы, инициированные сервером, задайте для `PLAYWRIGHT_MCP_PING_TIMEOUT_MS` более длительный тайм-аут в миллисекундах. Установите значение `0`, чтобы отключить проверку активности.

Затем укажите HTTP-адрес сервера в своём MCP-клиенте:

```json
{
  "mcpServers": {
    "playwright": {
      "url": "http://localhost:8931/mcp"
    }
  }
}
```
