Playwright предоставляет мощный интерфейс командной строки для запуска тестов, генерации кода, отладки и многого другого. Самый актуальный список команд и аргументов CLI всегда можно получить с помощью `npx playwright --help`.

## Основные команды {#essential-commands}

### Запуск тестов {#run-tests}

Запускает ваши тесты Playwright. [Подробнее о запуске тестов](./running-tests.mdx).

#### Синтаксис {#syntax}

```bash
npx playwright test [options] [test-filter...]
```

#### Примеры {#examples}

```bash
# Запустить все тесты
npx playwright test

# Запустить один файл тестов
npx playwright test tests/todo-page.spec.ts

# Запустить набор файлов тестов
npx playwright test tests/todo-page/ tests/landing-page/

# Запустить тесты на конкретной строке
npx playwright test my-spec.ts:42

# Запустить тесты по заголовку
npx playwright test -g "add a todo item"

# Запустить тесты в headed-режиме
npx playwright test --headed

# Запустить тесты для конкретного проекта
npx playwright test --project=chromium

# Справка
npx playwright test --help
```

**Отключить [параллелизацию](./test-parallel.mdx)**

```bash
npx playwright test --workers=1
```

**Запуск в режиме отладки с [Playwright Inspector](./debug.mdx)**

```bash
npx playwright test --debug
```

**Запуск тестов в интерактивном [UI mode](./test-ui-mode.mdx)**

```bash
npx playwright test --ui
```

#### Часто используемые опции {#common-options}

| Опция | Описание |
| :--- | :--- |
| `--debug [mode]` | Запустить тесты с Playwright Inspector. Сокращение для переменной окружения `PWDEBUG=1` и параметров `--timeout=0 --max-failures=1 --headed --workers=1`. Необязательный режим — "inspector" (по умолчанию) или "cli": режим "cli" позволяет подключаться и выполнять отладку через интерфейс командной строки. |
| `--headed` | Запустить тесты в браузерах с графическим интерфейсом (по умолчанию: без графического интерфейса). |
| `-g <grep>` or `--grep <grep>` | Запустить только тесты, соответствующие этому регулярному выражению (по умолчанию: ".*"). |
| `--project <project-name...>` | Запустить только тесты из указанного списка проектов; поддерживается подстановочный символ '*' (по умолчанию: запускать все проекты). |
| `--ui` | Запустить тесты в интерактивном режиме с пользовательским интерфейсом. |
| `-j <workers>` or `--workers <workers>` | Количество параллельных рабочих процессов или процент от числа логических ядер процессора; используйте 1 для запуска в одном рабочем процессе (по умолчанию: 50%). |

#### Все опции {#all-options}

| Опция | Описание |
| :--- | :--- |
| Аргументы, не являющиеся опциями | Каждый аргумент рассматривается как регулярное выражение, сопоставляемое с полным путём к файлу теста. Будут выполнены только тесты из файлов, соответствующих шаблону. Специальные символы, такие как `$` или `*`, следует экранировать с помощью `\`. Во многих оболочках и терминалах может потребоваться заключить аргументы в кавычки. |
| `--add-reporter <reporter>` | Репортёры, добавляемые к репортёрам, настроенным в файле конфигурации, через запятую. Можно указать имя встроенного репортёра или путь к файлу пользовательского репортёра. В отличие от `--reporter`, эта опция сохраняет настроенные репортёры, а не заменяет их. |
| `-c <file>` или `--config <file>` | Файл конфигурации или каталог с тестами, в котором может находиться файл "playwright.config.&#123;m,c&#125;?&#123;js,ts&#125;". По умолчанию используется `playwright.config.ts` или `playwright.config.js` в текущем каталоге. |
| `--debug [mode]` | Запуск тестов с Playwright Inspector. Сокращение для переменной окружения `PWDEBUG=1` и опций `--timeout=0 --max-failures=1 --headed --workers=1`. Необязательный режим — "inspector" (по умолчанию) или "cli"; режим "cli" позволяет подключаться и выполнять отладку через CLI. |
| `--fail-on-flaky-tests` | Завершать запуск с ошибкой, если хотя бы один тест помечен как нестабильный (по умолчанию: false). |
| `--forbid-only` | Завершать запуск с ошибкой при вызове `test.only` (по умолчанию: false). Полезно в CI. |
| `--fully-parallel` | Запускать все тесты параллельно (по умолчанию: false). |
| `--global-timeout <timeout>` | Максимальное время выполнения этого набора тестов в миллисекундах (по умолчанию: без ограничений). |
| `-g <grep>` или `--grep <grep>` | Запускать только тесты, соответствующие этому регулярному выражению (по умолчанию: ".*"). |
| `-G <grep>` или `--grep-invert <grep>` | Запускать только тесты, не соответствующие этому регулярному выражению. |
| `--headed` | Запускать тесты в браузерах с графическим интерфейсом (по умолчанию: без графического интерфейса). |
| `--ignore-snapshots` | Игнорировать проверки скриншотов и снимков. |
| `-j <workers>` или `--workers <workers>` | Количество одновременно работающих рабочих процессов или процент от числа логических ядер процессора; укажите 1 для запуска в одном рабочем процессе (по умолчанию: 50%). |
| `--last-failed` | Повторно запускать только тесты, завершившиеся с ошибкой. |
| `--last-failed-file <file>` | Переопределить путь по умолчанию к JSON-файлу с результатами последнего запуска для `--last-failed` (по умолчанию: `<outputDir>/.last-run.json`). Эквивалентно переменной окружения `PLAYWRIGHT_LAST_RUN_OUTPUT_FILE`. |
| `--list` | Собрать все тесты и вывести сведения о них, но не запускать их. |
| `--max-failures <N>` или `-x` | Остановить выполнение после первых `N` ошибок. При передаче `-x` выполнение останавливается после первой ошибки. |
| `--no-deps` | Не запускать зависимости проектов. |
| `--output <dir>` | Каталог для выходных артефактов (по умолчанию: "test-results"). |
| `--only-changed [ref]` | Запускать только файлы тестов, изменённые между 'HEAD' и 'ref'. По умолчанию запускаются тесты для всех незафиксированных изменений. Поддерживается только Git. |
| `--pass-with-no-tests` | Считать запуск успешным, даже если тесты не найдены. |
| `--project <project-name...>` | Запускать тесты только из указанного списка проектов; поддерживается подстановочный символ '*' (по умолчанию: запускать все проекты). |
| `--quiet` | Подавлять стандартный вывод и вывод ошибок (stdio). |
| `--repeat-each <N>` | Запускать каждый тест `N` раз (по умолчанию: 1). |
| `--reporter <reporter>` | Используемые репортёры, через запятую; можно указать "dot", "line", "list", "failures" или другие (по умолчанию: "list" локально и "dot" в CI). Также можно передать путь к файлу пользовательского репортёра. |
| `--retries <retries>` | Максимальное количество повторных попыток для нестабильных тестов; ноль — без повторных попыток (по умолчанию: без повторных попыток). |
| `--run-agents <mode>` | Запускать агентов для генерации кода для `page.perform`. Возможные значения: "missing", "all" и "none" (по умолчанию: "none"). См. [агенты тестирования](./test-agents.mdx). |
| `--shard <shard>` | Разделить тесты на части и выполнить только выбранную часть, указанную в формате "current/all", с нумерацией от 1, например "3/5". |
| `--shuffle [seed]` | Планировать выполнение тестов в случайном порядке: перемешиваются файлы тестов, а в [параллельном режиме](./test-parallel.mdx) — и отдельные тесты. Тесты, которые должны выполняться вместе, например в последовательном наборе, сохраняют свой порядок. Начальное значение генератора случайных чисел выводится в начале запуска; передайте его, чтобы воспроизвести тот же порядок. |
| `--test-list <file>` | Путь к файлу, содержащему список тестов для запуска. Подробнее см. в разделе [список тестов](#test-list). |
| `--test-list-invert <file>` | Путь к файлу, содержащему список тестов, которые нужно пропустить. Подробнее см. в разделе [список тестов](#test-list).  |
| `--timeout <timeout>` | Указать предельное время выполнения теста в миллисекундах; ноль — без ограничений (по умолчанию: 30 секунд). |
| `--trace <mode>` | Принудительно задать режим трассировки; возможные значения: `on`, `off`, `on-first-retry`, `on-all-retries`, `retain-on-failure`, `retain-on-first-failure`, `retain-on-failure-and-retries`. |
| `--tsconfig <path>` | Путь к единому файлу tsconfig, применяемому ко всем импортируемым файлам (по умолчанию: искать tsconfig отдельно для каждого импортируемого файла). |
| `--ui` | Запускать тесты в интерактивном режиме UI. |
| `--ui-host <host>` | Хост для предоставления UI; при указании этой опции UI открывается во вкладке браузера. |
| `--ui-port <port>` | Порт для предоставления UI; 0 — любой свободный порт. При указании этой опции UI открывается во вкладке браузера. |
| `-u` или `--update-snapshots [mode]` | Обновлять снимки фактическими результатами. Возможные значения: "all", "changed", "missing", "none" и "default". При запуске тестов без этого флага по умолчанию используется "default"; при запуске с флагом, но без значения — "changed". |
| `--update-source-method <method>` | Выбрать способ обновления исходного кода. Возможные значения: "patch" (по умолчанию), "3way" и "overwrite". "Patch" создаёт файл различий в формате unified diff, который можно использовать для последующего обновления исходного кода. "3way" добавляет маркеры конфликтов слияния в исходный код. "Overwrite" перезаписывает исходный код, подставляя новые значения снимков.|
| `-x` | Остановить выполнение после первой ошибки. |

#### Список тестов {#test-list}

Опции `--test-list` и `--test-list-invert` принимают путь к файлу со списком тестов. Этот файл должен перечислять тесты в формате, похожем на вывод режима `--list`.

```txt
# Это файл со списком тестов.
# В нём могут быть комментарии и пустые строки.

# Запустить ВСЕ тесты в файле:
path/to/example.spec.ts

# Запустить все тесты в файле для определённого проекта:
[chromium] › path/to/example.spec.ts

# Запустить все тесты в определённой группе/наборе:
path/to/example.spec.ts › suite name

# Запустить все тесты во вложенной группе:
path/to/example.spec.ts › outer suite › inner suite

# Полностью квалифицированное имя теста с указанием проекта:
[chromium] › path/to/example.spec.ts:3:9 › suite › nested suite › example test

# Этот тест включён для всех проектов:
path/to/example.spec.ts:3:9 › example test

# В качестве разделителя можно использовать "›" или ">":
[firefox] > example.spec.ts > suite > nested suite > example test

# Номера строки/колонки полностью игнорируются — их можно опустить.
# Три записи ниже относятся к одному и тому же тесту:
example.spec.ts › example test
example.spec.ts:15 › example test
example.spec.ts:42:42 › example test
```

### Показать отчёт {#show-report}

Показать HTML-отчёт из предыдущего запуска тестов. [Подробнее об HTML-репортёре](./test-reporters#html-reporter).

#### Синтаксис {#syntax-1}

```bash
npx playwright show-report [report] [options]
```

#### Примеры {#examples-1}

```bash
# Show latest test report
npx playwright show-report

# Show a specific report
npx playwright show-report playwright-report/

# Show report on custom port
npx playwright show-report --port 8080
```

#### Параметры {#options}

| Option | Description |
| :--- | :--- |
| | `--host <host>` | Хост, на котором будет запущен сервер отчёта (по умолчанию: localhost) |
| | `--port <port>` | Порт для сервера отчёта (по умолчанию: 9323) |

### Установка браузеров {#install-browsers}

Установить браузеры, необходимые для Playwright. [Подробнее о поддержке браузеров в Playwright](./browsers.mdx).

#### Синтаксис {#syntax-2}

```bash
npx playwright install [options] [browser...]
npx playwright install-deps [options] [browser...]
npx playwright uninstall
```

#### Примеры {#examples-2}

```bash
# Install all browsers
npx playwright install

# Install only Chromium
npx playwright install chromium

# Install specific browsers
npx playwright install chromium webkit

# Install browsers with dependencies
npx playwright install --with-deps
```

#### Параметры установки {#install-options}

| Option | Description |
| :--- | :--- |
| `--force` | Принудительно переустановить уже установленные браузеры |
| `--with-deps` | Установить системные зависимости браузеров |
| `--dry-run` | Не выполнять установку, а только вывести информацию |
| `--list` | Вывести список браузеров из всех установок Playwright |
| `--only-shell` | Установить только chromium-headless-shell вместо полной версии Chromium |
| `--no-shell` | Не устанавливать chromium-headless-shell |
| `--no-progress` | Не показывать индикаторы хода загрузки |
| `--no-remove` | Не удалять неиспользуемые браузеры |

#### Параметры установки зависимостей {#install-deps-options}

| Option | Description |
| :--- | :--- |
| `--dry-run` | Проверяет установку без изменений системы. В Linux имитирует установку через apt-get и возвращает ненулевой код, если требуемые пакеты отсутствуют. Это удобно для автоматических проверок. В Windows выводит команду установки. |

## Инструменты генерации и отладки {#generation-debugging-tools}

### Генерация кода {#code-generation}

Записывайте действия и генерируйте тесты для нескольких языков. [Подробнее о Codegen](./codegen-intro.mdx).

#### Синтаксис {#syntax-3}

```bash
npx playwright codegen [options] [url]
```

#### Примеры {#examples-3}

```bash
# Start recording with interactive UI
npx playwright codegen

# Record on specific site
npx playwright codegen https://playwright.dev

# Generate Python code
npx playwright codegen --target=python
```

#### Параметры {#options-1}

| Option | Description |
| :--- | :--- |
| `-b, --browser <name>` | Используемый браузер: chromium, firefox или webkit (по умолчанию: chromium) |
| `-o, --output <file>` | Выходной файл для сгенерированного скрипта |
| `--target <language>` | Используемый язык: javascript, playwright-test, python и т. д. |
| `--test-id-attribute <attr>` | Атрибут для использования в качестве идентификаторов тестов |

### Просмотрщик трассировки {#trace-viewer}

Анализируйте и просматривайте трассы тестов для отладки. [Подробнее о Trace Viewer](./trace-viewer.mdx).
 
#### Синтаксис {#syntax-4}

```bash
npx playwright show-trace [options] [trace]
```

#### Примеры {#examples-4}

```bash
# Open trace viewer without a specific trace (can load traces via UI)
npx playwright show-trace

# View a trace file
npx playwright show-trace trace.zip

# View trace from directory
npx playwright show-trace trace/
```
 
#### Options {#options-2}

| Option | Description |
| :--- | :--- |
| `-b, --browser <name>` | Используемый браузер: chromium, firefox или webkit (по умолчанию: chromium) |
| `-h, --host <host>` | Хост для публикации трассировки |
| | `-p, --port <port>` | Порт для сервера трассировки |
 
## Специализированные команды {#specialized-commands}
 
### Объединение отчётов {#merge-reports}
 
Прочитать отчёты [blob](./test-reporters#blob-reporter) и объединить их. [Подробнее о merge-reports](./test-sharding.mdx).

При передаче `--port` другие пользователи вашего компьютера могут открыть трассировку на этом порту. При передаче `--host` любой, кто имеет доступ к указанному адресу и порту, может открыть трассировку. Например, при использовании `--host=0.0.0.0` это могут сделать пользователи других компьютеров в вашей сети.

## Специализированные команды

### Объединение отчётов

Чтение и объединение отчётов в формате [blob](./test-reporters#blob-reporter). [Подробнее о merge-reports](./test-sharding.mdx).

#### Синтаксис

```bash
npx playwright merge-reports [options] <blob dir>
```

#### Примеры {#examples-5}

```bash
# Combine test reports
npx playwright merge-reports ./reports
```

#### Параметры {#options-3}

| Параметр | Описание |
| :--- | :--- |
| `-c, --config <file>` | Файл конфигурации. Можно использовать для указания дополнительной конфигурации выходного отчёта |
| `--reporter <reporter>` | Используемый репортёр; можно указать несколько через запятую. Допустимые значения: "list", "line", "dot", "failures", "json", "junit", "null", "github", "html", "blob", "perfetto" (по умолчанию: "list" при локальном запуске и "dot" в CI) |

### Очистка кеша

Очистить все кеши Playwright.

#### Синтаксис

```bash
npx playwright clear-cache
```

Playwright хранит транспилированные тесты в системном временном каталоге. Чтобы выбрать другой каталог, например на общем сервере Linux, задайте переменную окружения `PLAYWRIGHT_TRANSFORM_CACHE_DIR`:

```bash
PLAYWRIGHT_TRANSFORM_CACHE_DIR=~/.cache/playwright-transform npx playwright test
```
