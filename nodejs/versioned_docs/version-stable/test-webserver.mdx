## Введение {#introduction}

В Playwright есть опция `webServer` в файле конфигурации, которая позволяет запускать локальный dev-сервер перед выполнением тестов. Это идеально при написании тестов во время разработки, а также когда у вас нет staging- или production-URL для тестирования.

## Настройка веб-сервера {#configuring-a-web-server}

Используйте свойство `webServer` в конфигурации Playwright, чтобы запускать dev-веб‑сервер во время выполнения тестов.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  // Запустите ваш локальный сервер разработки перед началом тестов
  webServer: {
    command: 'npm run start',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
    stdout: 'ignore',
    stderr: 'pipe',
  },
});
```

| Свойство | Описание |
| :- | :- |
| [testConfig.webServer](/api/class-testconfig.mdx#test-config-web-server) | Запуск одного или нескольких веб-серверов для разработки во время выполнения тестов. |
| `command`| Команда оболочки для запуска локального сервера разработки вашего приложения. |
| `cwd` | Текущий рабочий каталог запускаемого процесса. По умолчанию используется каталог файла конфигурации. |
| `env` | Переменные окружения для команды. По умолчанию наследуются переменные из `process.env` с добавлением `PLAYWRIGHT_TEST=1`. |
| `gracefulShutdown` | Способ завершения процесса. Если параметр не указан, группа процессов принудительно завершается сигналом `SIGKILL`. Если задано `{ signal: 'SIGTERM', timeout: 500 }`, группе процессов отправляется сигнал `SIGTERM`, а затем — `SIGKILL`, если она не завершится в течение 500 мс. Вместо `SIGTERM` также можно использовать сигнал `SIGINT`. Тайм-аут `0` означает, что сигнал `SIGKILL` не будет отправлен. Windows не поддерживает сигналы `SIGTERM` и `SIGINT`, поэтому в Windows этот параметр игнорируется. Обратите внимание, что для завершения работы контейнера Docker требуется `SIGTERM`. |
| `ignoreHTTPSErrors` | Игнорировать ли ошибки HTTPS при обращении к `url`. По умолчанию — `false`. |
| `name` | Задает пользовательское имя веб-сервера. Это имя будет добавляться в начало сообщений журнала. По умолчанию — `[WebServer]`. |
| `port` | **Устарело**. Используйте `url` вместо этого параметра. Порт, на котором ожидается запуск вашего HTTP-сервера. Выполнение будет ожидать, пока сервер не начнет принимать соединения. Необходимо указать либо `port`, либо `url`. |
| `reuseExistingServer`| Если задано `true`, уже работающий сервер на указанном `port` или по указанному `url` будет использован повторно, если он доступен. Если на этом `port` или по этому `url` сервер не запущен, будет выполнена команда для запуска нового сервера. Если задано `false`, будет выброшено исключение, если существующий процесс уже принимает соединения на указанном `port` или по указанному `url`. Обычно этому параметру следует задавать значение `!process.env.CI`, чтобы разрешить использование локального сервера разработки при локальном запуске тестов. |
| `stderr` | Перенаправлять ли стандартный поток ошибок команды в стандартный поток ошибок процесса или игнорировать его. По умолчанию — `"pipe"`. |
| `stdout` | Если задано `"pipe"`, стандартный поток вывода команды перенаправляется в стандартный поток вывода процесса. Если задано `"ignore"`, стандартный поток вывода команды игнорируется. По умолчанию — `"ignore"`. |
| `timeout` | Время ожидания запуска процесса и его готовности к работе в миллисекундах. По умолчанию — 60000. |
| `url`| URL вашего HTTP-сервера, который должен возвращать код состояния 2xx, 3xx, 400, 401, 402 или 403, когда сервер готов принимать соединения. Необходимо указать либо `port`, либо `url`. Если указаны и `url`, и `wait`, сервер считается запущенным, когда выполнено хотя бы одно из условий. |
| `wait` | Считать команду запущенной только после появления заданного вывода. Принимает объект с необязательными регулярными выражениями `stdout` и/или `stderr`. Именованные группы захвата в регулярном выражении сохраняются в переменных окружения. Например, `/Listening on port (?<my_server_port>\d+)/` сохранит номер порта в `process.env['MY_SERVER_PORT']`. Если указаны и `url`, и `wait`, сервер считается запущенным, когда выполнено хотя бы одно из условий. |

## Добавление таймаута для сервера {#adding-a-server-timeout}

Веб-серверам иногда требуется больше времени для запуска. В этом случае вы можете увеличить таймаут, чтобы дождаться старта сервера.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  // Остальная часть вашей конфигурации...

  // Запустите ваш локальный сервер разработки перед началом тестов
  webServer: {
    command: 'npm run start',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
    timeout: 120 * 1000,
  },
});
```

## Добавление baseURL {#adding-a-baseurl}

Также рекомендуется указать `baseURL` в секции `use: {}` вашей конфигурации, чтобы тесты могли использовать относительные URL и вам не приходилось постоянно указывать полный URL.

При использовании [page.goto()](/api/class-page.mdx#page-goto), [page.route()](/api/class-page.mdx#page-route), [page.waitForURL()](/api/class-page.mdx#page-wait-for-url), [page.waitForRequest()](/api/class-page.mdx#page-wait-for-request) или [page.waitForResponse()](/api/class-page.mdx#page-wait-for-response) учитывается базовый URL с помощью конструктора [`URL()`](https://developer.mozilla.org/en-US/docs/Web/API/URL/URL) для построения соответствующего URL. Например, установив baseURL на `http://localhost:3000` и переходя к `/login` в ваших тестах, Playwright выполнит тест, используя `http://localhost:3000/login`.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  // Остальная часть вашей конфигурации...

  // Запустите ваш локальный сервер разработки перед началом тестов
  webServer: {
    command: 'npm run start',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
  },
  use: {
    baseURL: 'http://localhost:3000',
  },
});
```

Теперь вы можете использовать относительный путь при навигации по странице:

```js title="test.spec.ts"
import { test } from '@playwright/test';

test('test', async ({ page }) => {
  // Это приведет к переходу на http://localhost:3000/login
  await page.goto('./login');
});
```

## Несколько веб-серверов {#multiple-web-servers}

Несколько веб-серверов (или фоновых процессов) могут быть запущены одновременно, предоставив массив конфигураций `webServer`. См. [testConfig.webServer](/api/class-testconfig.mdx#test-config-web-server) для получения дополнительной информации.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  webServer: [
    {
      command: 'npm run start',
      url: 'http://localhost:3000',
      name: 'Frontend',
      timeout: 120 * 1000,
      reuseExistingServer: !process.env.CI,
    },
    {
      command: 'npm run backend',
      url: 'http://localhost:3333',
      name: 'Backend',
      timeout: 120 * 1000,
      reuseExistingServer: !process.env.CI,
    }
  ],
  use: {
    baseURL: 'http://localhost:3000',
  },
});
```
