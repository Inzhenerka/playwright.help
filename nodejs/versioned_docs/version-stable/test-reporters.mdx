## Введение {#introduction}

Playwright Test поставляется с несколькими встроенными отчётчиками для различных нужд и возможностью предоставления пользовательских отчётчиков. Самый простой способ попробовать встроенные отчётчики — это передать опцию командной строки `--reporter`.

```bash
npx playwright test --reporter=line
```

Для большего контроля вы можете указать отчётчики программно в [файле конфигурации](./test-configuration.mdx).

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: 'line',
});
```

### Несколько отчётчиков {#multiple-reporters}

Вы можете использовать несколько отчётчиков одновременно. Например, вы можете использовать `'list'` для красивого вывода в терминале и `'json'`, чтобы получить подробный json-файл с результатами тестов.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [
    ['list'],
    ['json', {  outputFile: 'test-results.json' }]
  ],
});
```

### Отчётчики на CI {#reporters-on-ci}

Вы можете использовать разные отчётчики локально и на CI. Например, использование лаконичного отчётчика `'dot'` позволяет избежать избыточного вывода. Это значение по умолчанию на CI.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  // Лаконичный 'dot' для CI, по умолчанию 'list' при локальном запуске
  reporter: process.env.CI ? 'dot' : 'list',
});
```

### Отчёт только о сбоях {/* #report-only-failures */}

Используйте `onlyFailures` с репортерами JSON, JUnit или HTML, чтобы включать в отчёт только тесты с неожиданными результатами (включая неожиданные успешные результаты), нестабильные тесты и прерванные тесты. Нестабильные тесты включаются в отчёт, даже если они проходят при повторном запуске. Для каждого включённого теста сохраняются все попытки выполнения, в том числе успешные повторные запуски:

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['html', { onlyFailures: true }]],
});
```

Настраивайте `onlyFailures` отдельно для каждого репортера. Чтобы использовать эту настройку при объединении blob-отчётов, передайте файл конфигурации в команду `npx playwright merge-reports --config=playwright.config.ts ./blob-report`.

Используйте репортер `failures`, чтобы выводить диагностическую информацию в терминал по мере выполнения тестов без отображения прогресса. Например, можно сохранять полный HTML-отчёт, одновременно выводя в терминал краткую информацию:

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['failures'], ['html']],
});
```

## Встроенные репортеры

Все встроенные отчётчики показывают подробную информацию о сбоях и в основном различаются по степени подробности для успешных запусков.

### Отчётчик List {#list-reporter}

Отчётчик List является значением по умолчанию (за исключением CI, где по умолчанию используется отчётчик `dot`). Он выводит строку для каждого выполняемого теста.

```bash
npx playwright test --reporter=list
```

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: 'list',
});
```

Вот пример вывода в процессе выполнения тестов. По умолчанию информация о сбоях будет выведена в конце.

```bash
npx playwright test --reporter=list
Running 124 tests using 6 workers

 1  ✓ should access error in env (438ms)
 2  ✓ handle long test names (515ms)
 3  x 1) render expected (691ms)
 4  ✓ should timeout (932ms)
 5    should repeat each:
 6  ✓ should respect enclosing .gitignore (569ms)
 7    should teardown env after timeout:
 8    should respect excluded tests:
 9  ✓ should handle env beforeEach error (638ms)
10    should respect enclosing .gitignore:
```

Вы можете включить отображение шагов, передав следующую опцию конфигурации:

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['list', { printSteps: true }]],
});
```

Вы можете выводить информацию об ошибках сразу по мере их появления, не дожидаясь завершения запуска:

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['list', { printFailuresInline: true }]],
});
```

Вы можете не выводить теги тестов, которые автоматически добавляются к названиям тестов:

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['list', { omitTags: true }]],
});
```

Репортёр List поддерживает следующие параметры конфигурации и переменные окружения:

| Имя переменной окружения | Опция конфигурации отчётчика | Описание | По умолчанию |
|---|---|---|---|
| `PLAYWRIGHT_LIST_PRINT_STEPS` | `printSteps` | Выводить ли каждый шаг в отдельной строке. | `false`
| `PLAYWRIGHT_LIST_PRINT_FAILURES_INLINE` | `printFailuresInline` | Выводить ли подробности ошибок сразу после неудачного теста, а не в конце. | `false`
| `PLAYWRIGHT_LIST_OMIT_TAGS` | `omitTags` | Скрывать ли теги тестов, автоматически добавляемые к названиям тестов. | `false`
| `PLAYWRIGHT_FORCE_TTY` | | Формировать ли вывод, подходящий для интерактивного терминала. Поддерживаются значения `true`, `1`, `false`, `0`, `[WIDTH]` и `[WIDTH]x[HEIGHT]`. Значения `[WIDTH]` и `[WIDTH]x[HEIGHT]` задают размеры TTY. | `true`, если терминал работает в режиме TTY, иначе `false`.
| `FORCE_COLOR` | | Использовать ли цветной вывод. | `true`, если терминал работает в режиме TTY, иначе `false`.
| `NO_COLOR` | | Отключать ли цветной вывод ([no-color.org](https://no-color.org/)). Любое непустое значение отключает цвета. | не задано

### Отчётчик Line {#line-reporter}

Отчётчик Line более лаконичен, чем отчётчик List. Он использует одну строку для отчёта о последнем завершённом тесте и выводит сбои по мере их возникновения. Отчётчик Line полезен для больших наборов тестов, где он показывает прогресс, но не засоряет вывод, перечисляя все тесты.

```bash
npx playwright test --reporter=line
```

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: 'line',
});
```

Вот пример вывода в середине выполнения теста. Сбои сообщаются в строке.

```bash
npx playwright test --reporter=line
Running 124 tests using 6 workers
  1) dot-reporter.spec.ts:20:1 › render expected ===================================================

    Error: expect(received).toBe(expected) // Object.is equality

    Expected: 1
    Received: 0

[23/124] gitignore.spec.ts - should respect nested .gitignore
```

Отчёт Line поддерживает следующие параметры конфигурации и переменные окружения:

| Имя переменной окружения | Опция конфигурации отчётчика | Описание | По умолчанию |
|---|---|---|---|
| `PLAYWRIGHT_LINE_OMIT_TAGS` | `omitTags` | Определяет, следует ли исключать теги тестов, которые автоматически добавляются к названиям тестов. | `false`
| `PLAYWRIGHT_FORCE_TTY` | | Определяет, следует ли формировать вывод, подходящий для интерактивного терминала. Поддерживает значения `true`, `1`, `false`, `0`, `[WIDTH]` и `[WIDTH]x[HEIGHT]`. Значения `[WIDTH]` и `[WIDTH]x[HEIGHT]` задают размеры TTY. | `true`, когда терминал находится в режиме TTY, в противном случае — `false`.
| `FORCE_COLOR` | | Определяет, следует ли использовать цветной вывод. | `true`, когда терминал находится в режиме TTY, в противном случае — `false`.
| `NO_COLOR` | | Определяет, следует ли отключать цветной вывод ([no-color.org](https://no-color.org/)). Любое непустое значение отключает цвета. | не задано

### Отчётчик Dot {#dot-reporter}

Отчётчик Dot очень лаконичен — он выводит только один символ для каждого успешного выполнения теста. Это значение по умолчанию на CI и полезно, когда вы не хотите большого объёма вывода.

```bash
npx playwright test --reporter=dot
```

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: 'dot',
});
```

Вот пример вывода в середине выполнения теста. Сбои будут перечислены в конце.

```bash
npx playwright test --reporter=dot
Running 124 tests using 6 workers
······F·············································
```

Один символ отображается для каждого выполненного теста, указывая его статус:

| Символ | Описание
|---|---|
| `·` | Пройден
| `F` | Провален
| `×` | Провален или истекло время - будет повторен
| `±` | Пройден при повторе (нестабильный)
| `T` | Истекло время
| `°` | Пропущен

Отчёт Dot поддерживает следующие параметры конфигурации и переменные окружения:

| Имя переменной окружения | Опция конфигурации отчётчика | Описание | По умолчанию |
|---|---|---|---|
| `PLAYWRIGHT_DOT_OMIT_TAGS` | `omitTags` | Следует ли скрывать теги тестов, автоматически добавляемые к названиям тестов. | `false`
| `PLAYWRIGHT_FORCE_TTY` | | Следует ли формировать вывод, подходящий для интерактивного терминала. Поддерживает значения `true`, `1`, `false`, `0`, `[WIDTH]` и `[WIDTH]x[HEIGHT]`. Значения `[WIDTH]` и `[WIDTH]x[HEIGHT]` задают размеры TTY. | `true`, если терминал находится в режиме TTY, иначе `false`.
| `FORCE_COLOR` | | Следует ли использовать цветной вывод. | `true`, если терминал находится в режиме TTY, иначе `false`.
| `NO_COLOR` | | Следует ли отключать цветной вывод ([no-color.org](https://no-color.org/)). Любое непустое значение отключает цвета. | не задано

### Репортёр failures {/* #failures-reporter */}

Репортёр failures выводит информацию о сбоях и успешных повторных запусках по мере их возникновения, а затем — итоговую сводку.

```bash
npx playwright test --reporter=failures
```

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: 'failures',
});
```

Используйте [testConfig.quiet](/api/class-testconfig.mdx#test-config-quiet), чтобы подавить вывод тестов в stdout и stderr.

Репортёр failures поддерживает следующие параметры конфигурации и переменные окружения:

| Имя переменной окружения | Параметр конфигурации репортёра | Описание | Значение по умолчанию |
|---|---|---|---|
| `PLAYWRIGHT_FAILURES_OMIT_TAGS` | `omitTags` | Следует ли скрывать теги тестов, добавляемые к названиям тестов. | `false` |
| `PLAYWRIGHT_FORCE_TTY` | | Следует ли формировать вывод, подходящий для интерактивного терминала. | `true`, если терминал находится в режиме TTY, иначе `false` |
| `FORCE_COLOR` | | Следует ли использовать цветной вывод. | `true`, если терминал находится в режиме TTY, иначе `false` |
| `NO_COLOR` | | Следует ли отключать цветной вывод. | не задано |

### Отчётчик HTML {#html-reporter}

Отчётчик HTML создаёт автономную папку, содержащую отчёт о выполнении теста, который можно открыть как веб-страницу.

```bash
npx playwright test --reporter=html
```

По умолчанию HTML-отчёт открывается автоматически, если некоторые из тестов не прошли. Вы можете контролировать это поведение с помощью свойства `open` в конфигурации Playwright или переменной окружения `PLAYWRIGHT_HTML_OPEN`. Возможные значения для этого свойства: `always`, `never` и `on-failure` (по умолчанию).

Вы также можете настроить `host` и `port`, которые используются для предоставления HTML-отчёта.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['html', { open: 'never' }]],
});
```

По умолчанию отчёт сохраняется в папку `playwright-report` в каталоге, содержащем package.json, или в текущем рабочем каталоге (если package.json не найден). Это расположение можно переопределить с помощью переменной окружения `PLAYWRIGHT_HTML_OUTPUT_DIR` или настройки репортера.

В файле конфигурации передайте параметры напрямую:

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['html', { outputFolder: 'my-report' }]],
});
```

Если вы загружаете вложения из папки данных в другое место, можно использовать опцию `attachmentsBaseURL`, чтобы HTML-отчёт знал, где их искать.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['html', { attachmentsBaseURL: 'https://external-storage.com/' }]],
});
```

Быстрый способ открыть отчёт о последнем запуске теста:

```bash
npx playwright show-report
```

Или если указано нестандартное имя папки:

```bash
npx playwright show-report my-report
```

Также можно передать архив `.zip` — например, скачанный из артефактов CI. Архив должен содержать файл `index.html` на верхнем уровне. Playwright распакует его во временный каталог и запустит сервер для просмотра отчёта:

```bash
npx playwright show-report playwright-report.zip
```

HTML-отчёт поддерживает следующие параметры конфигурации и переменные окружения:

| Имя переменной окружения | Опция конфигурации отчётчика | Описание | По умолчанию |
|---|---|---|---|
| `PLAYWRIGHT_HTML_TITLE` | `title` | Заголовок, отображаемый в сгенерированном отчёте. | По умолчанию заголовок не отображается
| `PLAYWRIGHT_HTML_ONLY_FAILURES` | `onlyFailures` | Включать только тесты с неожиданными результатами, нестабильные тесты (включая успешные повторные попытки) и прерванные тесты. См. [Отчёт только о сбоях](#report-only-failures). | `false`
| `PLAYWRIGHT_HTML_OUTPUT_DIR` | `outputFolder` | Каталог для сохранения отчёта. | `playwright-report`
| `PLAYWRIGHT_HTML_OPEN` | `open` | Когда открывать HTML-отчёт в браузере: `'always'`, `'never'` или `'on-failure'` | `'on-failure'`
| `PLAYWRIGHT_HTML_HOST` | `host` | При открытии отчёта в браузере сервер будет привязан к этому имени хоста. | `localhost`
| `PLAYWRIGHT_HTML_PORT` | `port` | При открытии отчёта в браузере сервер будет использовать этот порт. | `9323` или любой доступный порт, если `9323` недоступен.
| `PLAYWRIGHT_HTML_ATTACHMENTS_BASE_URL` | `attachmentsBaseURL` | Отдельное расположение, куда загружаются вложения из подкаталога `data`. Требуется только в том случае, если отчёт и `data` загружаются отдельно в разные расположения. | `data/`
| `PLAYWRIGHT_HTML_NO_COPY_PROMPT` | `noCopyPrompt` | Если установлено значение true, отключает отображение кнопки «Copy prompt» для ошибок. Поддерживает значения `true`, `1`, `false` и `0`. | `false`
| `PLAYWRIGHT_HTML_NO_SNIPPETS` | `noSnippets` | Если установлено значение true, отключает отображение фрагментов кода в журнале действий. При наличии ошибки верхнего уровня соответствующий раздел отчёта с фрагментом кода всё равно будет отображаться. Поддерживает значения `true`, `1`, `false` и `0`. | `false`
| `PLAYWRIGHT_HTML_DO_NOT_INLINE_ASSETS` | `doNotInlineAssets` | Если установлено значение true, JavaScript, CSS и данные отчёта записываются в отдельные файлы рядом с `index.html`, а не встраиваются в него. Используйте этот параметр при размещении отчёта со строгой [политикой безопасности содержимого (Content Security Policy)](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP), запрещающей встроенные скрипты и стили. Поддерживает значения `true`, `1`, `false` и `0`. | `false`
| `PLAYWRIGHT_HTML_MERGE_FILES` | `mergeFiles` | Если установлено значение true, тесты группируются по заголовку блока `test.describe()` верхнего уровня, а не по файлу, которому они принадлежат. Поддерживает значения `true`, `1`, `false` и `0`. | `false`

### Отчётчик Blob {#blob-reporter}

Отчёты Blob содержат все детали о выполнении теста и могут быть использованы позже для создания любого другого отчёта. Их основная функция — облегчить объединение отчётов из [разделённых тестов](./test-sharding.mdx).

```bash
npx playwright test --reporter=blob
```

По умолчанию отчёт записывается в директорию `blob-report` в директории с package.json или в текущей рабочей директории (если package.json не найден).

Имя файла отчёта имеет вид `report-<hash>.zip` или `report-<hash>-<shard_number>.zip`, если используется [шардирование](./test-sharding.mdx). Хеш — это необязательное значение, вычисляемое на основе `--grep`, `--grep-invert`, `--project`, [testConfig.tag](/api/class-testconfig.mdx#test-config-tag) и фильтров файлов, переданных в качестве аргументов командной строки. Хеш гарантирует, что запуск Playwright с разными параметрами командной строки будет создавать отчёты с разными именами, которые при этом остаются неизменными между запусками с одинаковыми параметрами. Имя выходного файла можно переопределить в файле конфигурации или задать с помощью переменной окружения `'PLAYWRIGHT_BLOB_OUTPUT_FILE'`.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';
```

При запуске тестов в разных окружениях можно использовать [testConfig.tag](/api/class-testconfig.mdx#test-config-tag), чтобы добавить глобальный тег, соответствующий окружению. Этот тег сделает объединённый отчёт более понятным и будет использоваться для формирования уникального имени blob-отчёта.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: 'blob',

});
```

Blob-отчёт поддерживает следующие опции конфигурации и переменные окружения:

| Имя переменной окружения | Опция конфигурации отчётчика | Описание | По умолчанию
|---|---|---|---|
| `PLAYWRIGHT_BLOB_OUTPUT_DIR` | `outputDir` | Каталог для сохранения результатов. Существующее содержимое удаляется перед записью нового отчёта. | `blob-report`
| `PLAYWRIGHT_BLOB_OUTPUT_NAME` | `fileName` | Имя файла отчёта. | `report-<hash>-<shard_number>.zip`

### Отчётчик JSON {#json-reporter}

### Репортёр Perfetto {/* #perfetto-reporter */}

Репортёр Perfetto создаёт JSON-файл в формате [Trace Event Format](https://docs.google.com/document/d/1CvAClvFfyA5R-PhYUmn5OOQtYMH4h6I0nSsKchNAySU/preview), который можно открыть в [интерфейсе Perfetto](https://ui.perfetto.dev) или в `chrome://tracing`. Он представляет запуск тестов в виде временной шкалы с отдельной дорожкой для каждого рабочего процесса, где каждый тест отображается как сегмент, содержащий хуки до и после выполнения, фикстуры и шаги в виде вложенных сегментов. Каждый сегмент содержит подробные сведения о тесте или шаге в аргументах события трассировки, включая расположение в исходном коде, [testStep.params](/api/class-teststep.mdx#test-step-params), теги, аннотации, ошибки, стандартные потоки ввода-вывода и пути к файлам вложений.

```bash
npx playwright test --reporter=perfetto
```

По умолчанию отчёт записывается в `test-results/perfetto.json`. Если имя выходного файла заканчивается на `.gz`, отчёт сжимается с помощью gzip на лету. Оба средства просмотра поддерживают этот формат, и такое сжатие особенно полезно при больших запусках тестов.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [['perfetto', { outputFile: 'perfetto.json.gz' }]],
});
```

Отчёт Perfetto поддерживает следующие параметры конфигурации и переменные окружения:

| Имя переменной окружения | Параметр конфигурации репортёра| Описание | Значение по умолчанию
|---|---|---|---|
| `PLAYWRIGHT_PERFETTO_OUTPUT_DIR` | | Каталог для сохранения выходного файла. Игнорируется, если указан выходной файл. | `test-results`
| `PLAYWRIGHT_PERFETTO_OUTPUT_NAME` | | Базовое имя выходного файла относительно каталога вывода. | `perfetto.json`
| `PLAYWRIGHT_PERFETTO_OUTPUT_FILE` | `outputFile` | Полный путь к выходному файлу. Если задан, `PLAYWRIGHT_PERFETTO_OUTPUT_DIR` и `PLAYWRIGHT_PERFETTO_OUTPUT_NAME` игнорируются. | `undefined`

### Аннотации GitHub Actions

Вы можете использовать встроенный отчётчик `github`, чтобы получить автоматические аннотации сбоев при запуске в GitHub Actions.

Обратите внимание, что все другие отчётчики также работают в GitHub Actions, но не предоставляют аннотаций. Также не рекомендуется использовать этот тип аннотаций, если вы запускаете тесты с помощью стратегии матрицы, так как сбои в трассировке стека будут умножаться и затруднять просмотр файлов в GitHub.

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  // 'github' для GitHub Actions CI для генерации аннотаций, плюс лаконичный 'dot'
  // по умолчанию 'list' при локальном запуске
  reporter: process.env.CI ? 'github' : 'list',
});
```

Репортёр `github` поддерживает параметр `omitTags` (или переменную окружения `PLAYWRIGHT_GITHUB_OMIT_TAGS`), позволяющий скрыть теги тестов в аннотациях, например: `reporter: [['github', { omitTags: true }]]`.

## Пользовательские репортёры

Вы можете создать пользовательский отчётчик, реализовав класс с некоторыми методами отчётчика. Узнайте больше о [Reporter] API.

```js title="my-awesome-reporter.ts"
import type {
  FullConfig, FullResult, Reporter, Suite, TestCase, TestResult
} from '@playwright/test/reporter';

class MyReporter implements Reporter {
  onBegin(config: FullConfig, suite: Suite) {
    console.log(`Starting the run with ${suite.allTests().length} tests`);
  }

  onTestBegin(test: TestCase, result: TestResult) {
    console.log(`Starting test ${test.title}`);
  }

  onTestEnd(test: TestCase, result: TestResult) {
    console.log(`Finished test ${test.title}: ${result.status}`);
  }

  onEnd(result: FullResult) {
    console.log(`Finished the run: ${result.status}`);
  }
}

export default MyReporter;
```

Теперь используйте этот отчётчик с [testConfig.reporter](/api/class-testconfig.mdx#test-config-reporter).

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: './my-awesome-reporter.ts',
});
```

Или просто передайте путь к файлу отчётчика в качестве опции командной строки `--reporter`:

```bash
npx playwright test --reporter="./myreporter/my-awesome-reporter.ts"
```
