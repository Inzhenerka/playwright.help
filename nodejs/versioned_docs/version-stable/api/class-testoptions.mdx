Playwright Test предоставляет множество опций для настройки тестовой среды, [Browser], [BrowserContext] и других.

Эти опции обычно указываются в [файле конфигурации](../test-configuration.mdx) через [testConfig.use](/api/class-testconfig.mdx#test-config-use) и [testProject.use](/api/class-testproject.mdx#test-project-use).

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';
export default defineConfig({
  use: {
    headless: false,
    viewport: { width: 1280, height: 720 },
    ignoreHTTPSErrors: true,
    video: 'on-first-retry',
  },
});
```

Кроме того, с помощью [test.use()](/api/class-test.mdx#test-use) вы можете переопределить некоторые опции для файла.

```js title="example.spec.ts"
import { test, expect } from '@playwright/test';

// Запуск тестов в этом файле с портретным видом.
test.use({ viewport: { width: 600, height: 900 } });

test('my portrait test', async ({ page }) => {
  // ...
});
```

### baseURL {/* #test-options-base-url */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.10</font><x-search>testOptions.baseURL</x-search>

При использовании [page.goto()](/api/class-page.mdx#page-goto), [page.route()](/api/class-page.mdx#page-route), [page.waitForURL()](/api/class-page.mdx#page-wait-for-url), [page.waitForRequest()](/api/class-page.mdx#page-wait-for-request) или [page.waitForResponse()](/api/class-page.mdx#page-wait-for-response) учитывается базовый URL, используя конструктор [`URL()`](https://developer.mozilla.org/en-US/docs/Web/API/URL/URL) для построения соответствующего URL. По умолчанию не установлен. Примеры:
* baseURL: `http://localhost:3000` и переход на `/bar.html` приводит к `http://localhost:3000/bar.html`
* baseURL: `http://localhost:3000/foo/` и переход на `./bar.html` приводит к `http://localhost:3000/foo/bar.html`
* baseURL: `http://localhost:3000/foo` (без завершающего слэша) и переход на `./bar.html` приводит к `http://localhost:3000/bar.html`

**Использование**

```js
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  use: {
    /* Базовый URL для использования в действиях, таких как `await page.goto('/')`. */
    baseURL: 'http://localhost:3000',
  },
});
```

**Тип**
- [string]

### clientCertificates {/* #test-options-client-certificates */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.46</font><x-search>testOptions.clientCertificates</x-search>

Аутентификация клиента TLS позволяет серверу запросить клиентский сертификат и проверить его.

**Использование**

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    clientCertificates: [{
      origin: 'https://example.com',
      certPath: './cert.pem',
      keyPath: './key.pem',
      passphrase: 'mysecretpassword',
    }],
  },
});
```

**Тип**
- [Array]&lt;[Object]&gt;
  - `origin` [string]
    
    Точный источник, для которого сертификат действителен. Источник включает протокол `https`, имя хоста и, возможно, порт.
  - `certPath` [string] (опционально)
    
    Путь к файлу с сертификатом в формате PEM.
  - `cert` [Buffer] (опционально)
    
    Прямое значение сертификата в формате PEM.
  - `keyPath` [string] (опционально)
    
    Путь к файлу с закрытым ключом в формате PEM.
  - `key` [Buffer] (опционально)
    
    Прямое значение закрытого ключа в формате PEM.
  - `pfxPath` [string] (опционально)
    
    Путь к PFX или PKCS12 закодированному закрытому ключу и цепочке сертификатов.
  - `pfx` [Buffer] (опционально)
    
    Прямое значение PFX или PKCS12 закодированного закрытого ключа и цепочки сертификатов.
  - `passphrase` [string] (опционально)
    
    Пароль для закрытого ключа (PEM или PFX).

**Детали**

Массив клиентских сертификатов для использования. Каждый объект сертификата должен иметь либо оба `certPath` и `keyPath`, либо один `pfxPath`, или их соответствующие прямые значения (`cert` и `key`, или `pfx`). При необходимости, свойство `passphrase` должно быть предоставлено, если сертификат зашифрован. Свойство `origin` должно быть предоставлено с точным совпадением с источником запроса, для которого сертификат действителен.

Аутентификация по клиентскому сертификату активна только если предоставлен хотя бы один клиентский сертификат. Если вы хотите отклонять все клиентские сертификаты, отправляемые сервером, нужно предоставить клиентский сертификат с `origin`, который не совпадает ни с одним из доменов, которые вы планируете посещать.

:::note

При использовании WebKit на macOS доступ к `localhost` не будет использовать клиентские сертификаты. Вы можете сделать это, заменив `localhost` на `local.playwright`.
:::

### connectOptions {/* #test-options-connect-options */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.10</font><x-search>testOptions.connectOptions</x-search>

**Использование**

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    connectOptions: {
      wsEndpoint: 'ws://localhost:5678',
    },
  },
});
```

Если указаны параметры подключения, стандартные фикстуры [fixtures.browser](/api/class-fixtures.mdx#fixtures-browser), [fixtures.context](/api/class-fixtures.mdx#fixtures-context) и [fixtures.page](/api/class-fixtures.mdx#fixtures-page) используют удалённый браузер вместо запуска браузера локально.

**Тип**
- [void] | [Object]
  - `wsEndpoint` [string]
    
    Веб-сокетный конечный пункт браузера для подключения.
  - `headers` [void] | [Object]&lt;[string], [string]&gt; (опционально)
    
    Дополнительные HTTP-заголовки для отправки с запросом на подключение веб-сокета. Необязательно.
  - `timeout` [number] (опционально)
    
    Тайм-аут в миллисекундах для установления соединения. Необязательно, по умолчанию без тайм-аута.
  - `exposeNetwork` [string] (опционально)
    
    Опция для предоставления сети, доступной на подключающемся клиенте, браузеру, к которому подключаются. Подробнее см. [browserType.connect()](/api/class-browsertype.mdx#browser-type-connect).

### httpCredentials {/* #test-options-http-credentials */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.10</font><x-search>testOptions.httpCredentials</x-search>

Учетные данные для [HTTP-аутентификации](https://developer.mozilla.org/en-US/docs/Web/HTTP/Authentication). Если источник не указан, имя пользователя и пароль отправляются на любые серверы при неавторизованных ответах.

Передайте массив, чтобы использовать разные учётные данные для разных источников (origin). Используется первая запись, соответствующая источнику запроса, а записи без указанного источника соответствуют любому запросу.

**Использование**

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    httpCredentials: {
      username: 'user',
      password: 'pass',
    },
  },
});
```

При передаче массива учётных данных в [test.use()](/api/class-test.mdx#test-use) оберните его в дополнительный массив, см. [параметры фикстур](../test-fixtures.mdx#fixtures-options).

```js title="example.spec.ts"
test.use({
  httpCredentials: [[
    { username: 'alice', password: 'alice-pass', origin: 'https://a.example.com' },
    { username: 'bob', password: 'bob-pass', origin: 'https://b.example.com' },
  ], { scope: 'test' }],
});
```

**Тип**
- [Object] | [Array]&lt;[Object]&gt;
  - `username` [string]
    
    
  - `password` [string]
    
    
  - `origin` [string] (опционально)
    
    Ограничить отправку http-учетных данных на конкретный источник (scheme://host:port).
  - `send` "unauthorized" | "always" (опционально)
    
    Эта опция применяется только к запросам, отправленным из соответствующего [APIRequestContext], и не влияет на запросы, отправленные из браузера. `'always'` - заголовок `Authorization` с учетными данными базовой аутентификации будет отправлен с каждым API-запросом. `'unauthorized` - учетные данные отправляются только при получении ответа 401 (Unauthorized) с заголовком `WWW-Authenticate`. По умолчанию `'unauthorized'`.

});

### trace {/* #test-options-trace */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.10</font><x-search>testOptions.trace</x-search>

Определяет, следует ли записывать трассировку для каждого теста. По умолчанию — `'off'`. Первоначальный запуск теста называется «первым запуском»; последующие запуски, вызванные [повторными попытками](../test-retries.mdx), называются «повторными попытками».
* `'off'`: Не записывать трассировку.
* `'on'`: Записывать и сохранять трассировку для каждого запуска.
* `'on-first-retry'`: Записывать и сохранять трассировку только для первой повторной попытки теста.
* `'on-all-retries'`: Записывать и сохранять трассировку для каждой повторной попытки.
* `'retain-on-failure'`: Записывать трассировку для каждого запуска, но сохранять её только для запусков, завершившихся с ошибкой. Трассировка запуска, завершившегося с ошибкой, сохраняется, даже если последующая повторная попытка завершилась успешно.
* `'retain-on-first-failure'`: Записывать трассировку только для первого запуска теста (не для повторных попыток) и сохранять её только в том случае, если этот запуск завершился с ошибкой.
* `'retain-on-failure-and-retries'`: Записывать трассировку для каждого запуска и сохранять её для любого запуска, который завершился с ошибкой или является повторной попыткой.

См. [режимы трассировки](../test-use-options.mdx#trace-modes), где приведено наглядное сравнение того, что записывает и сохраняет каждый режим.

Для более точного контроля передайте объект, который указывает `mode` и функции трассировки для включения.

**Использование**

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    trace: 'on-first-retry'
  },
});
```

Узнайте больше о [записи трассировки](../test-use-options.mdx#recording-options).

**Тип**
- [Object] | "off" | "on" | "on-first-retry" | "on-all-retries" | "retain-on-failure" | "retain-on-first-failure" | "retain-on-failure-and-retries"
  - `mode` "off" | "on" | "retain-on-failure" | "on-first-retry" | "on-all-retries" | "retain-on-first-failure" | "retain-on-failure-and-retries"
    
    Режим записи трассировки.
  - `attachments` [boolean] (опционально)
    
    Включать ли вложения теста. По умолчанию true. Необязательно.
  - `screenshots` [boolean] (опционально)
    
Определяет, следует ли делать скриншоты во время трассировки. Скриншоты используются для предварительного просмотра на временной шкале. По умолчанию true. Необязательный параметр.
  - `snapshots` [boolean] | [Object] *(необязательный)*
    - `dom` [boolean] *(необязательный)*
      
      Создавать снимок DOM при каждом действии и записывать сетевую активность. Необязательный параметр.
    - `aria` [boolean] *(необязательный)*
      
      Создавать ARIA-снимок страницы при каждом действии. Необязательный параметр.
    - `screen` [boolean] *(необязательный)*
      
      Делать скриншот страницы при каждом действии. Необязательный параметр.
    
    Определяет, какие снимки создавать при каждом действии. Передача `true` эквивалентна `{ dom: true }`. По умолчанию true. Необязательный параметр.
  - `sources` [boolean] *(необязательный)*
    
    Включать ли исходные файлы для действий трассировки. По умолчанию true. Необязательно.

### video {/* #test-options-video */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.10</font><x-search>testOptions.video</x-search>

Определяет, следует ли записывать видео для каждого теста. По умолчанию — `'off'`. Начальный запуск теста называется «первым запуском»; последующие запуски, вызванные [повторными попытками](../test-retries.mdx), называются «повторными попытками».
* `'off'`: Не записывать видео.
* `'on'`: Записывать и сохранять видео для каждого запуска.
* `'on-first-retry'`: Записывать и сохранять видео только для первой повторной попытки выполнения теста.
* `'on-all-retries'`: Записывать и сохранять видео для каждой повторной попытки.
* `'retain-on-failure'`: Записывать видео для каждого запуска, но сохранять его только для запусков, завершившихся с ошибкой. Видео неудачного запуска сохраняется, даже если последующая повторная попытка завершается успешно.
* `'retain-on-first-failure'`: Записывать видео только для первого запуска теста (но не для повторных попыток) и сохранять его только в том случае, если этот запуск завершился с ошибкой.
* `'retain-on-failure-and-retries'`: Записывать видео для каждого запуска и сохранять его для любого запуска, который завершился с ошибкой или является повторной попыткой.

См. раздел [режимы записи видео](../test-use-options.mdx#video-modes), где приведено наглядное сравнение того, какие запуски записываются и какие видеозаписи сохраняются в каждом режиме.

Чтобы контролировать размер видео, передайте объект с свойствами `mode` и `size`. Если размер видео не указан, он будет равен [testOptions.viewport](/api/class-testoptions.mdx#test-options-viewport), уменьшенному для соответствия 800x800. Если `viewport` не настроен явно, размер видео по умолчанию составляет 800x450. Фактическое изображение каждой страницы будет уменьшено, если необходимо, чтобы соответствовать указанному размеру.

Чтобы записывать более плавное видео анимаций и прокрутки, передайте `fps`, например `{ mode: 'on', size: { width: 1920, height: 1080 }, fps: 60 }`. Более высокая частота кадров и больший размер видео увеличивают нагрузку на процессор при кодировании. В настоящее время Firefox и WebKit захватывают до 25 кадров в секунду.

Чтобы добавлять аннотации действий в видео, передайте `show` с вложенными параметрами `actions` и/или `test`. Параметр `actions` управляет визуальным выделением элементов, с которыми выполняется взаимодействие. Продолжительность каждого выделения можно задать с помощью необязательного параметра `duration` в миллисекундах (по умолчанию — `500`). Параметр `test` определяет, какая информация о тесте отображается в виде наложения со статусом.

**Использование**

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    video: 'on-first-retry',
  },
});
```

Узнайте больше о [записи видео](../test-use-options.mdx#recording-options).

**Тип**

### viewport {/* #test-options-viewport */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.10</font><x-search>testOptions.viewport</x-search>

Эмулирует постоянную видовую область для каждой страницы. По умолчанию используется видовая область 1280x720. Используйте `null`, чтобы отключить эмуляцию постоянной видовой области. Узнайте больше о [эмуляции видовой области](../emulation#viewport).

:::note

Значение `null` исключает использование предустановок по умолчанию, делает видовую область зависимой от размера окна хоста, определяемого операционной системой. Это делает выполнение тестов недетерминированным.
:::

**Использование**

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  use: {
    viewport: { width: 100, height: 100 },
  },
});
```

**Тип**
- [null] | [Object]
  - `width` [number]
    
    ширина страницы в пикселях.
  - `height` [number]
    
    высота страницы в пикселях.

## Deprecated

### reuseContext {/* #test-options-reuse-context */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.62</font><x-search>testOptions.reuseContext</x-search>

:::warning[Discouraged]

Эта опция ускоряет компонентные тесты с галереей сценариев за счёт изоляции. Для сквозных тестов оставьте её выключенной, чтобы каждый тест получал отдельный контекст браузера.

:::


**Экспериментальная опция.** При значении `true` все тесты в одном воркере используют общий контекст браузера. По умолчанию `false`.

Между тестами Playwright очищает файлы cookie, кэш, localStorage и IndexedDB посещённых источников, отменяет регистрацию сервис-воркеров, закрывает лишние страницы, удаляет маршруты, привязки и скрипты инициализации, а затем заново применяет настроенное состояние хранилища, размер области просмотра и параметры эмуляции.

Этот сброс не гарантирует полной изоляции. Сохраняются:
* Разрешения, выданные через [browserContext.grantPermissions()](/api/class-browsercontext.mdx#browser-context-grant-permissions) во время теста.
* Изменения, внесённые во время теста через [browserContext.setGeolocation()](/api/class-browsercontext.mdx#browser-context-set-geolocation), [browserContext.setOffline()](/api/class-browsercontext.mdx#browser-context-set-offline) и [browserContext.setExtraHTTPHeaders()](/api/class-browsercontext.mdx#browser-context-set-extra-http-headers).
* История навигации, `window.name` и состояние, общее для процесса браузера.

Дополнительные ограничения:
* При включённой записи [testOptions.video](/api/class-testoptions.mdx#test-options-video) опция игнорируется.
* Между соседними тестами могут отличаться только `colorScheme`, `forcedColors`, `reducedMotion`, `contrast`, `screen`, `userAgent`, `viewport` и `testIdAttribute`. Изменение любой другой настройки через [test.use()](/api/class-test.mdx#test-use), например `locale` или `storageState`, создаёт новый контекст и сводит ускорение на нет.
* Не сочетайте с [testOptions.connectOptions](/api/class-testoptions.mdx#test-options-connect-options), если несколько воркеров подключаются к одному браузеру. Они будут конкурировать за один контекст.
* Параметр `recordHar` в [testOptions.contextOptions](/api/class-testoptions.mdx#test-options-context-options) не поддерживается. Файл HAR не создаётся.

**Использование**

```js title="playwright.config.ts"
import { defineConfig } from '@playwright/test';

export default defineConfig({
  projects: [
    {
      name: 'components',
      testDir: './tests/components',
      use: { reuseContext: true },
    },
  ],
});
```
