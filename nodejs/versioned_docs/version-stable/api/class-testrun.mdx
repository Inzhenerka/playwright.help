Управляет тем, какие тесты будут запущены и каков их ожидаемый статус, а также предоставляет информацию о режимах выполнения наборов тестов. Объект [TestRun] доступен во время вызова [reporter.preprocess()](/api/class-reporter.mdx#reporter-preprocess). Проекты настройки и очистки (setup и teardown) изменять нельзя.


---

## Методы

### exclude {/* #test-run-exclude */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.62</font><x-search>testRun.exclude</x-search>

Исключает тест или набор тестов из запуска. Исключённые тесты не отображаются в отчёте, а их тела не выполняются.

**Использование**

```js
testRun.exclude(test);
```

**Аргументы**
- `test` [TestCase] | [Suite]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-exclude-option-test"/><a href="#test-run-exclude-option-test" class="list-anchor">#</a>
  
  Тест или набор тестов, который нужно исключить. Корневой набор тестов исключить нельзя.

---

### fail {/* #test-run-fail */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.62</font><x-search>testRun.fail</x-search>

Помечает тест или каждый тест в наборе как «должен завершиться с ошибкой». Playwright запускает эти тесты и проверяет, что они действительно завершаются с ошибкой. Это полезно для документирования неработающей функциональности до её исправления.

**Использование**

```js
testRun.fail(test);
testRun.fail(test, reason);
```

**Аргументы**
- `test` [TestCase] | [Suite]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-fail-option-test"/><a href="#test-run-fail-option-test" class="list-anchor">#</a>
  
  Тест или набор тестов, для которого нужно отметить ожидаемое завершение с ошибкой.
- `reason` [string] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-fail-option-reason"/><a href="#test-run-fail-option-reason" class="list-anchor">#</a>
  
  Необязательное пояснение, которое отображается в описании аннотации.

### fixme {/* #test-run-fixme */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.62</font><x-search>testRun.fixme</x-search>

Помечает тест или каждый тест в наборе как fixme. Тела тестов не выполняются, а сами тесты отображаются в отчёте как пропущенные с намерением исправить их в дальнейшем.

**Использование**

```js
testRun.fixme(test);
testRun.fixme(test, reason);
```

**Аргументы**
- `test` [TestCase] | [Suite]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-fixme-option-test"/><a href="#test-run-fixme-option-test" class="list-anchor">#</a>
  
  Тест или набор тестов, который нужно пометить как fixme.
- `reason` [string] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-fixme-option-reason"/><a href="#test-run-fixme-option-reason" class="list-anchor">#</a>
  
  Необязательное пояснение, которое отображается в описании аннотации.

### mode {/* #test-run-mode */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.65</font><x-search>testRun.mode</x-search>

Возвращает режим выполнения, настроенный для набора тестов с помощью [test.describe.configure()](/api/class-test.mdx#test-describe-configure), [test.describe.serial()](/api/class-test.mdx#test-describe-serial) или [test.describe.parallel()](/api/class-test.mdx#test-describe-parallel). Если для набора режим не настроен, он наследует режим родительского набора. Наборы тестов проектов используют `"parallel"`, когда включён [testProject.fullyParallel](/api/class-testproject.mdx#test-project-fully-parallel), и `"default"` в противном случае. Корневой набор тестов использует `"default"`.

Набор тестов с явно заданным режимом `"default"` не наследует `"parallel"` от родительского набора: его тесты выполняются по порядку в одном и том же рабочем процессе. Сам по себе режим не определяет полностью группы выполнения тестов, которые также зависят от фикстур рабочего процесса и хуков.

Этот метод можно вызывать только во время [reporter.preprocess()](/api/class-reporter.mdx#reporter-preprocess). Он также позволяет проверять режим проектов настройки и очистки (setup и teardown).

**Использование**

```js
testRun.mode(suite);
```

**Аргументы**
- `suite` [Suite]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-mode-option-suite"/><a href="#test-run-mode-option-suite" class="list-anchor">#</a>
  
  Набор тестов, режим которого нужно проверить.

**Возвращает**
- "serial" | "parallel" | "default"<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-mode-return"/><a href="#test-run-mode-return" class="list-anchor">#</a>

### skip {/* #test-run-skip */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.62</font><x-search>testRun.skip</x-search>

Пропускает тест или каждый тест в наборе. Тела тестов не выполняются, а сами тесты отображаются в отчёте как пропущенные.

**Использование**

```js
testRun.skip(test);
testRun.skip(test, reason);
```

**Аргументы**
- `test` [TestCase] | [Suite]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-skip-option-test"/><a href="#test-run-skip-option-test" class="list-anchor">#</a>
  
  Тест или набор тестов, который нужно пропустить.
- `reason` [string] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="test-run-skip-option-reason"/><a href="#test-run-skip-option-reason" class="list-anchor">#</a>
  
  Необязательное пояснение, которое отображается в описании аннотации.

---

### skipSharding {/* #test-run-skip-sharding */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.62</font><x-search>testRun.skipSharding</x-search>

Отключает встроенный фильтр шардов Playwright для текущего запуска, передавая распределение тестов по шардам репортёру. Репортёры обычно реализуют собственное распределение по шардам, вызывая [testRun.exclude()](/api/class-testrun.mdx#test-run-exclude) для тестов, не входящих в текущий шард.

**Использование**

```js
testRun.skipSharding();
```
