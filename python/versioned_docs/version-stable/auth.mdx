## Введение {#introduction}

Playwright выполняет тесты в изолированных средах, называемых [контекстами браузера](./browser-contexts.mdx). Эта модель изоляции улучшает воспроизводимость и предотвращает каскадные сбои тестов. Тесты могут загружать существующее аутентифицированное состояние. Это устраняет необходимость аутентификации в каждом тесте и ускоряет выполнение тестов.

## Основные концепции {#core-concepts}

Независимо от выбранной вами стратегии аутентификации, вы, вероятно, будете хранить аутентифицированное состояние браузера в файловой системе.

Мы рекомендуем создать каталог `playwright/.auth` и добавить его в ваш `.gitignore`. Ваша процедура аутентификации создаст аутентифицированное состояние браузера и сохранит его в файл в этом каталоге `playwright/.auth`. Впоследствии тесты будут повторно использовать это состояние и начинать уже аутентифицированными.

:::danger

Файл состояния браузера может содержать конфиденциальные файлы cookie и заголовки, которые могут быть использованы для выдачи себя за вас или вашу тестовую учетную запись. Мы настоятельно не рекомендуем добавлять их в частные или публичные репозитории.
:::

## Вход в систему перед каждым тестом {#signing-in-before-each-test}

API Playwright может [автоматизировать взаимодействие](./input.mdx) с формой входа.

Следующий пример выполняет вход в GitHub. После выполнения этих шагов контекст браузера будет аутентифицирован.

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
page = context.new_page()
page.goto('https://github.com/login')

# Взаимодействие с формой входа
page.get_by_label("Username or email address").fill("username")
page.get_by_label("Password").fill("password")
page.get_by_role("button", name="Sign in").click()
# Продолжение теста
```

</TabItem>
<TabItem value="async">

```py
page = await context.new_page()
await page.goto('https://github.com/login')

# Взаимодействие с формой входа
await page.get_by_label("Username or email address").fill("username")
await page.get_by_label("Password").fill("password")
await page.get_by_role("button", name="Sign in").click()
# Продолжение теста
```

</TabItem>
</Tabs>

Повторный вход в систему для каждого теста может замедлить выполнение тестов. Чтобы этого избежать, повторно используйте существующее аутентифицированное состояние.

## Повторное использование аутентифицированного состояния {#reusing-signed-in-state}

Playwright предоставляет способ повторного использования аутентифицированного состояния в тестах. Таким образом, вы можете войти в систему только один раз, а затем пропустить шаг входа для всех тестов.

Веб-приложения используют аутентификацию на основе файлов cookie или токенов, при которой состояние аутентификации хранится в [файлах cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Cookies), в [локальном хранилище](https://developer.mozilla.org/en-US/docs/Web/API/Storage), в [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) или в виде ключей доступа (passkeys — учётных данных [WebAuthn](https://developer.mozilla.org/en-US/docs/Web/API/Web_Authentication_API)). Playwright предоставляет метод [browser_context.storage_state()](/api/class-browsercontext.mdx#browser-context-storage-state), который позволяет получить состояние хранилища из контекстов, в которых выполнена аутентификация, а затем создать новые контексты с предварительно заполненным состоянием.

Файлы cookie, локальное хранилище, IndexedDB и виртуальные учётные данные WebAuthn (ключи доступа) можно использовать в разных браузерах. Их использование зависит от модели аутентификации вашего приложения, которая может требовать определённого сочетания файлов cookie, локального хранилища, IndexedDB или ключей доступа.

Следующий фрагмент кода получает состояние из контекста, в котором выполнена аутентификация, и создаёт новый контекст с этим состоянием. Если ваше приложение хранит токены аутентификации в IndexedDB, как, например, при использовании Firebase Authentication, включите параметр [indexed_db](/api/class-browsercontext.mdx#browser-context-storage-state-option-indexed-db) при сохранении состояния. По умолчанию IndexedDB не включается в снимок состояния.

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
# Сохранение состояния хранилища в файл.
storage = context.storage_state(path="state.json")

# Создание нового контекста с сохраненным состоянием хранилища.
context = browser.new_context(storage_state="state.json")
```

</TabItem>
<TabItem value="async">

```py
# Сохранение состояния хранилища в файл.
storage = await context.storage_state(path="state.json")

# Создание нового контекста с сохраненным состоянием хранилища.
context = await browser.new_context(storage_state="state.json")
```

</TabItem>
</Tabs>

## Продвинутые сценарии {#advanced-scenarios}

### Хранилище сессий {#session-storage}

Повторное использование состояния аутентификации охватывает аутентификацию на основе [файлов cookie](https://developer.mozilla.org/en-US/docs/Web/HTTP/Cookies), [локального хранилища](https://developer.mozilla.org/en-US/docs/Web/API/Storage), [IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API) и ключей доступа (passkey, [WebAuthn](https://developer.mozilla.org/en-US/docs/Web/API/Web_Authentication_API)). В редких случаях для хранения информации, связанной с состоянием входа в систему, используется [хранилище сеанса](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage). Хранилище сеанса привязано к определённому домену, и его содержимое не сохраняется между загрузками страниц. Playwright не предоставляет API для сохранения хранилища сеанса, однако для его сохранения и загрузки можно использовать следующий фрагмент кода.

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
import os
# Получение хранилища сессий и сохранение в переменную окружения
session_storage = page.evaluate("() => JSON.stringify(sessionStorage)")
os.environ["SESSION_STORAGE"] = session_storage

# Установка хранилища сессий в новом контексте
session_storage = os.environ["SESSION_STORAGE"]
escaped_session_storage = session_storage.replace("\\", "\\\\").replace("'", "\\'")
context.add_init_script("""(storage => {
  if (window.location.hostname === 'example.com') {
    const entries = JSON.parse(storage)
    for (const [key, value] of Object.entries(entries)) {
      window.sessionStorage.setItem(key, value)
    }
  }
})('""" + escaped_session_storage + "')")
```

</TabItem>
<TabItem value="async">

```py
import os
# Получение хранилища сессий и сохранение в переменную окружения
session_storage = await page.evaluate("() => JSON.stringify(sessionStorage)")
os.environ["SESSION_STORAGE"] = session_storage

# Установка хранилища сессий в новом контексте
session_storage = os.environ["SESSION_STORAGE"]
escaped_session_storage = session_storage.replace("\\", "\\\\").replace("'", "\\'")
await context.add_init_script("""(storage => {
  if (window.location.hostname === 'example.com') {
    const entries = JSON.parse(storage)
    for (const [key, value] of Object.entries(entries)) {
      window.sessionStorage.setItem(key, value)
    }
  }
})('""" + escaped_session_storage + "')")
```

</TabItem>
