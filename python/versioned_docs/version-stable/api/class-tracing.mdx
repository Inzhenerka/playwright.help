API для сбора и сохранения трасс (traces) Playwright. Трассы Playwright можно открыть в [Trace Viewer](../trace-viewer.mdx) после выполнения скрипта Playwright.

:::note

Скорее всего, вам стоит [включить трассировку в файле конфигурации](https://playwright.dev/docs/api/class-testoptions#test-options-trace), а не использовать `context.tracing`.

API `context.tracing` записывает операции браузера и сетевую активность, но не записывает ассерты тестов (например, вызовы `expect`). Мы рекомендуем [включать трассировку через конфигурацию Playwright Test](https://playwright.dev/docs/api/class-testoptions#test-options-trace): она включает и эти ассерты и даёт более полную трассу для отладки падений тестов.
:::

Начните запись трассы перед выполнением действий. В конце остановите трассировку и сохраните её в файл.

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
browser = chromium.launch()
context = browser.new_context()
context.tracing.start(screenshots=True, snapshots=True)
page = context.new_page()
page.goto("https://playwright.dev")
context.tracing.stop(path = "trace.zip")
```

</TabItem>
<TabItem value="async">

```py
browser = await chromium.launch()
context = await browser.new_context()
await context.tracing.start(screenshots=True, snapshots=True)
page = await context.new_page()
await page.goto("https://playwright.dev")
await context.tracing.stop(path = "trace.zip")
```

</TabItem>
</Tabs>

### group {/* #tracing-group */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.49</font><x-search>tracing.group</x-search>

:::caution

Используйте `test.step`, если доступно.
:::

Создает новую группу в пределах трассировки, назначая все последующие вызовы API этой группе, до тех пор, пока не будет вызван [tracing.group_end()](/api/class-tracing.mdx#tracing-group-end). Группы могут быть вложенными и будут видны в просмотрщике трассировок.

**Использование**

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
# Все действия между group и group_end
# будут показаны в просмотрщике трассировок как группа.
page.context.tracing.group("Open Playwright.dev > API")
page.goto("https://playwright.dev/")
page.get_by_role("link", name="API").click()
page.context.tracing.group_end()
```

</TabItem>
<TabItem value="async">

```py
# Все действия между group и group_end
# будут показаны в просмотрщике трассировок как группа.
await page.context.tracing.group("Open Playwright.dev > API")
await page.goto("https://playwright.dev/")
await page.get_by_role("link", name="API").click()
await page.context.tracing.group_end()
```

</TabItem>
</Tabs>

**Аргументы**

  Имя группы, отображаемое в просмотрщике трассировок.

  - `file` [str]
    
    
  - `line` [int] *(опционально)*
    
    
  - `column` [int] *(опционально)*
    
    
  Указывает пользовательское расположение для группы, которое будет показано в просмотрщике трассировок. По умолчанию используется расположение вызова [tracing.group()](/api/class-tracing.mdx#tracing-group).

**Возвращает**

### start {/* #tracing-start */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.12</font><x-search>tracing.start</x-search>

Запускает трассировку. Освобождение возвращённого объекта [Disposable] останавливает трассировку без сохранения результатов, аналогично вызову [tracing.stop()](/api/class-tracing.mdx#tracing-stop) без указания пути.

:::note

Скорее всего, вам стоит [включить трассировку в файле конфигурации](https://playwright.dev/docs/api/class-testoptions#test-options-trace), а не использовать `Tracing.start`.

API `context.tracing` записывает операции браузера и сетевую активность, но не записывает ассерты тестов (например, вызовы `expect`). Мы рекомендуем [включать трассировку через конфигурацию Playwright Test](https://playwright.dev/docs/api/class-testoptions#test-options-trace): она включает и эти ассерты и даёт более полную трассу для отладки падений тестов.
:::

### start_chunk {/* #tracing-start-chunk */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.15</font><x-search>tracing.start_chunk</x-search>

Начинает новый фрагмент трассировки. Освобождение возвращённого объекта [Disposable] останавливает фрагмент без его сохранения, аналогично вызову [tracing.stop_chunk()](/api/class-tracing.mdx#tracing-stop-chunk) без указания пути. Если вы хотите записать несколько трассировок в одном и том же [BrowserContext], вызовите [tracing.start()](/api/class-tracing.mdx#tracing-start) один раз, а затем создавайте отдельные фрагменты трассировки с помощью [tracing.start_chunk()](/api/class-tracing.mdx#tracing-start-chunk) и [tracing.stop_chunk()](/api/class-tracing.mdx#tracing-stop-chunk).

**Использование**

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
context.tracing.start(screenshots=True, snapshots=True)
page = context.new_page()
page.goto("https://playwright.dev")

context.tracing.start_chunk()
page.get_by_text("Get Started").click()
# Все между start_chunk и stop_chunk будет записано в трассировку.
context.tracing.stop_chunk(path = "trace1.zip")

context.tracing.start_chunk()
page.goto("http://example.com")
# Сохраните второй файл трассировки с другими действиями.
context.tracing.stop_chunk(path = "trace2.zip")
```

</TabItem>
<TabItem value="async">

```py
await context.tracing.start(screenshots=True, snapshots=True)
page = await context.new_page()
await page.goto("https://playwright.dev")

await context.tracing.start_chunk()
await page.get_by_text("Get Started").click()
# Все между start_chunk и stop_chunk будет записано в трассировку.
await context.tracing.stop_chunk(path = "trace1.zip")

await context.tracing.start_chunk()
await page.goto("http://example.com")
# Сохраните второй файл трассировки с другими действиями.
await context.tracing.stop_chunk(path = "trace2.zip")
```

</TabItem>
</Tabs>

  Если указано, промежуточные файлы трассировки будут сохранены в файлы с данным префиксом имени внутри директории [traces_dir](/api/class-browsertype.mdx#browser-type-launch-option-traces-dir), указанной в [browser_type.launch()](/api/class-browsertype.mdx#browser-type-launch). Чтобы указать имя конечного zip-файла трассировки, необходимо передать опцию `path` в [tracing.stop_chunk()](/api/class-tracing.mdx#tracing-stop-chunk).
- `title` [str] *(опционально)* <font size="2">Добавлено в: v1.17</font><a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="tracing-start-chunk-option-title"/><a href="#tracing-start-chunk-option-title" class="list-anchor">#</a>

### start_har {/* #tracing-start-har */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.60</font><x-search>tracing.start_har</x-search>

Начинает запись сетевой активности в этом контексте в формате HAR (HTTP Archive). Файл HAR записывается на диск при вызове [tracing.stop_har()](/api/class-tracing.mdx#tracing-stop-har) или при освобождении возвращённого объекта [Disposable].

Для каждого экземпляра [Tracing] одновременно может быть активна только одна запись HAR.

**Usage**

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
context.tracing.start_har("trace.har")
page = context.new_page()
page.goto("https://playwright.dev")
context.tracing.stop_har()
```

</TabItem>
<TabItem value="async">

```py
await context.tracing.start_har("trace.har")
page = await context.new_page()
await page.goto("https://playwright.dev")
await context.tracing.stop_har()
```

</TabItem>
</Tabs>

**Arguments**
- `path` [Union]\[[str], [pathlib.Path]\]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="tracing-start-har-option-path"/><a href="#tracing-start-har-option-path" class="list-anchor">#</a>
  
  Путь в файловой системе для записи файла HAR. Если имя файла заканчивается на `.zip`, HAR сохраняется как zip-архив с телами ответов в отдельных файлах.
- `content` "omit" | "embed" | "attach" *(optional)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="tracing-start-har-option-content"/><a href="#tracing-start-har-option-content" class="list-anchor">#</a>
  
  Необязательная настройка для управления содержимым ресурсов. Если указано `omit`, содержимое не сохраняется. Если указано `attach`, ресурсы сохраняются как отдельные файлы или записи в ZIP-архиве. Если указано `embed`, содержимое сохраняется непосредственно в файле HAR в соответствии со спецификацией HAR. По умолчанию используется `attach` для выходных файлов `.zip` и `embed` для всех остальных расширений файлов.
- `mode` "full" | "minimal" *(optional)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="tracing-start-har-option-mode"/><a href="#tracing-start-har-option-mode" class="list-anchor">#</a>
  
  Если задано значение `minimal`, записывается только информация, необходимая для маршрутизации из HAR. При этом не записываются размеры, временные характеристики, сведения о странице, файлы cookie, сведения о безопасности и другие типы информации HAR, которые не используются при воспроизведении из HAR. По умолчанию используется `full`.
- `url_filter` [str] | [Pattern] *(optional)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="tracing-start-har-option-url-filter"/><a href="#tracing-start-har-option-url-filter" class="list-anchor">#</a>
  
  Шаблон glob или регулярное выражение для фильтрации запросов, сохраняемых в HAR. По умолчанию фильтрация отсутствует.

**Returns**
- [Disposable]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="tracing-start-har-return"/><a href="#tracing-start-har-return" class="list-anchor">#</a>
