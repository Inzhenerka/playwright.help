`Credentials` — это виртуальный аутентификатор WebAuthn, действующий в пределах [BrowserContext]. Он позволяет тестам регистрировать ключи доступа (passkey) и обрабатывать процедуры `navigator.credentials.create()` / `navigator.credentials.get()` на странице без настоящего аутентификатора или аппаратного ключа безопасности.

Существует три распространённых способа его использования:

**Использование: добавление заранее известных учётных данных**

<Tabs
  groupId="python-flavor"
  defaultValue="sync"
  values={[
    {label: 'Sync', value: 'sync'},
    {label: 'Async', value: 'async'}
  ]
}>
<TabItem value="sync">

```py
context = browser.new_context()

# Ключ доступа, который ваш бэкенд уже подготовил для тестового пользователя.
context.credentials.create(
    "example.com",
    id=known_credential_id,  # base64url
    user_handle=known_user_handle,  # base64url
    private_key=known_private_key,  # base64url PKCS#8 (DER)
    public_key=known_public_key,  # base64url SPKI (DER)
)
context.credentials.install()

page = context.new_page()
page.goto("https://example.com/login")
# Вызов navigator.credentials.get() на странице получает добавленный ключ доступа.
```

</TabItem>

## Методы

### create {/* #credentials-create */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.create</x-search>

Добавляет учётные данные в виртуальный аутентификатор WebAuthn и возвращает их.

Если указан только [rp_id](/api/class-credentials.mdx#credentials-create-option-rp-id), генерирует новую пару ключей **ECDSA P-256**, идентификатор учётных данных и идентификатор пользователя. Добавленные учётные данные являются обнаруживаемыми (резидентными), поэтому страница может получить их как в сценарии ввода имени пользователя с последующим использованием ключа доступа, так и в сценарии использования ключа доступа без имени пользователя. Возвращаемый объект содержит закрытый и открытый ключи, поэтому его можно сохранить на диск и повторно добавить в последующем тесте.

Чтобы **импортировать известные учётные данные**, передайте все четыре параметра — [id](/api/class-credentials.mdx#credentials-create-option-id), [user_handle](/api/class-credentials.mdx#credentials-create-option-user-handle), [private_key](/api/class-credentials.mdx#credentials-create-option-private-key) и [public_key](/api/class-credentials.mdx#credentials-create-option-public-key) — одновременно. Также передайте [sign_count](/api/class-credentials.mdx#credentials-create-option-sign-count), чтобы продолжить отсчёт со значения счётчика подписей, которое доверяющая сторона уже получила.

Вызовите [credentials.install()](/api/class-credentials.mdx#credentials-install) перед переходом на страницу, использующую WebAuthn.

**Использование**

```python
credentials.create(rp_id)
credentials.create(rp_id, **kwargs)
```

**Аргументы**
- `rp_id` [str]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-rp-id"/><a href="#credentials-create-option-rp-id" class="list-anchor">#</a>
  
  Идентификатор доверяющей стороны (обычно действующий домен сайта).
- `id` [str] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-id"/><a href="#credentials-create-option-id" class="list-anchor">#</a>
  
  Идентификатор учётных данных в кодировке base64url. Генерируется автоматически, если не указан.
- `private_key` [str] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-private-key"/><a href="#credentials-create-option-private-key" class="list-anchor">#</a>
  
  Закрытый ключ PKCS#8 (DER) в кодировке base64url. Генерируется автоматически, если не указан.
- `public_key` [str] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-public-key"/><a href="#credentials-create-option-public-key" class="list-anchor">#</a>
  
  Открытый ключ SPKI (DER) в кодировке base64url. Генерируется автоматически, если не указан.
- `sign_count` [int] *(необязательно)* <font size="2">Добавлено в: v1.64</font><a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-sign-count"/><a href="#credentials-create-option-sign-count" class="list-anchor">#</a>
  
  Начальное значение [счётчика подписей](https://www.w3.org/TR/webauthn-2/#signature-counter). Счётчик увеличивается на единицу при каждом успешном подтверждении аутентификации через `navigator.credentials.get()`, поэтому первое подтверждение сообщает значение `signCount + 1`. По умолчанию — `0`.
- `user_handle` [str] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-option-user-handle"/><a href="#credentials-create-option-user-handle" class="list-anchor">#</a>
  
  Идентификатор пользователя в кодировке base64url. Генерируется автоматически, если не указан.

**Возвращаемое значение**
- [Dict]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-create-return"/><a href="#credentials-create-return" class="list-anchor">#</a>
  - `id` [str]
    
    Идентификатор учётных данных в кодировке base64url.
  - `rpId` [str]
    
    Идентификатор доверяющей стороны.
  - `userHandle` [str]
    
    Идентификатор пользователя в кодировке base64url.
  - `privateKey` [str]
    
    Закрытый ключ PKCS#8 (DER) в кодировке base64url.
  - `publicKey` [str]
    
    Открытый ключ SPKI (DER) в кодировке base64url.
  - `signCount` [int]
    
    Счётчик подписей: значение, переданное доверяющей стороне в последнем подтверждении аутентификации.

### delete {/* #credentials-delete */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.delete</x-search>

Работает с любыми учётными данными, которые в данный момент хранятся в аутентификаторе: как с добавленными через [credentials.create()](/api/class-credentials.mdx#credentials-create), так и с зарегистрированными самой страницей посредством вызова `navigator.credentials.create()`.

**Использование**

```python
credentials.delete(id)
```

### get {/* #credentials-get */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.get</x-search>

Возвращает все учётные данные, которые в данный момент хранятся в аутентификаторе, с возможностью фильтрации по [rp_id](/api/class-credentials.mdx#credentials-get-option-rp-id) или [id](/api/class-credentials.mdx#credentials-get-option-id). В их число входят как учётные данные, добавленные через [credentials.create()](/api/class-credentials.mdx#credentials-create), так и учётные данные, зарегистрированные самой страницей посредством вызова `navigator.credentials.create()`.

Каждый возвращаемый набор учётных данных включает закрытый и открытый ключи, а также текущее значение счётчика подписей. Поэтому ключ доступа, только что зарегистрированный приложением, можно сохранить и повторно добавить в последующем тесте с помощью [credentials.create()](/api/class-credentials.mdx#credentials-create) — см. второй пример в обзоре класса.

**Использование**

```python
credentials.get()
credentials.get(**kwargs)
```

**Аргументы**
- `id` [str] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-get-option-id"/><a href="#credentials-get-option-id" class="list-anchor">#</a>
  
  Возвращать только учётные данные с этим идентификатором в кодировке base64url.
- `rp_id` [str] *(необязательно)*<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-get-option-rp-id"/><a href="#credentials-get-option-rp-id" class="list-anchor">#</a>
  
  Возвращать только учётные данные для этого идентификатора доверяющей стороны.

**Возвращаемое значение**
- [List]\[[Dict]\]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-get-return"/><a href="#credentials-get-return" class="list-anchor">#</a>
  - `id` [str]
    
    
  - `rpId` [str]
    
    
  - `userHandle` [str]
    
    
  - `privateKey` [str]
    
    
  - `publicKey` [str]
    
    
  - `signCount` [int]

### install {/* #credentials-install */}

<font size="2" style={{position: "relative", top: "-20px"}}>Добавлено в: v1.61</font><x-search>credentials.install</x-search>

Устанавливает виртуальный аутентификатор WebAuthn в контекст, переопределяя `navigator.credentials.create()` и `navigator.credentials.get()` на всех существующих и будущих страницах. Вызовите этот метод до первого обращения страницы к `navigator.credentials`.

Обязательный шаг: до вызова [credentials.install()](/api/class-credentials.mdx#credentials-install) перехват не выполняется, и страница использует встроенную реализацию WebAuthn платформы (либо сталкивается с её отсутствием). Добавление учётных данных через [credentials.create()](/api/class-credentials.mdx#credentials-create) без установки аутентификатора заполняет его данными, но страница никогда не увидит эти учётные данные.

**Использование**

```python
credentials.install()
```

**Возвращаемое значение**
- [NoneType]<a aria-hidden="true" tabIndex="-1" class="list-anchor-link" id="credentials-install-return"/><a href="#credentials-install-return" class="list-anchor">#</a>
