# Профиль и состояние

Playwright MCP управляет состоянием браузера с помощью профилей. По умолчанию состояние авторизации и файлы cookie автоматически сохраняются между сеансами.

## Режимы профиля

### Постоянный (по умолчанию)

Состояние авторизации, файлы cookie и локальное хранилище сохраняются между сеансами. Имя каталога профиля включает канал браузера и хеш каталога рабочего пространства клиента, поэтому для разных проектов автоматически создаются отдельные профили.

| Платформа | Расположение по умолчанию |
|----------|-----------------|
| macOS | `~/Library/Caches/ms-playwright-mcp/mcp-{channel}-{workspace-hash}` |
| Linux | `~/.cache/ms-playwright-mcp/mcp-{channel}-{workspace-hash}` |
| Windows | `%LOCALAPPDATA%\ms-playwright-mcp\mcp-{channel}-{workspace-hash}` |

Чтобы переопределить расположение профиля:

```json
["@playwright/mcp@latest", "--user-data-dir=/path/to/profile"]
```

Профиль может использоваться только одним браузером одновременно. Если профиль уже заблокирован, сервер не запустится.

:::note
В отличие от MCP, [Playwright CLI](/agent-cli/introduction) по умолчанию хранит состояние **в памяти** (файлы cookie сохраняются между командами, но теряются при закрытии браузера). Используйте параметр `--persistent` в CLI, чтобы включить сохранение на диск. Подробнее об управлении сеансами в CLI см. в разделе [Сеансы и панель управления](/agent-cli/sessions).
:::

### Изолированный

Каждый сеанс начинается с чистого состояния, без сохранённых данных, и ничего не записывается на диск. Для включения этого режима передайте `--isolated`:

```json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest", "--isolated"]
    }
  }
}
```

Параметр `--isolated` нельзя использовать совместно с `--user-data-dir`. Чтобы загрузить начальное состояние в изолированный сеанс, используйте `--storage-state`:

```json
["@playwright/mcp@latest", "--isolated", "--storage-state=./auth-state.json"]
```

### Расширение браузера

Подключайтесь к существующим вкладкам браузера вместо запуска нового браузера. См. раздел [Расширение браузера](./browser-extension.mdx).

## Сохранение и восстановление состояния

Сохраните состояние авторизации для повторного использования в других сеансах с помощью возможности **storage**:

```txt
// Войдите в систему, затем сохраните состояние
→ browser_storage_state { filename: "auth-state.json" }
  - [Состояние хранилища](auth-state.json)

// Позже: восстановите состояние
→ browser_set_storage_state { filename: "auth-state.json" }
```

Или загружайте состояние автоматически при запуске сервера с помощью `--storage-state`. Полный порядок действий см. в разделе [Хранилище и аутентификация](../tools/storage.mdx).
